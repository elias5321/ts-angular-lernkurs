#part angular-app | Angular: eine App aus Bausteinen | Eigene Komponenten, Daten zwischen ihnen austauschen, Services, Formulare, mehrere Seiten und Daten aus dem Internet.

=== eigene-komponenten | Eigene Komponenten erstellen | 20
Bis jetzt stand alles in der Wurzelkomponente `App`. Eine echte App teilt man in viele kleine Komponenten auf. Jede hat eine klare Aufgabe, und man kann sie mehrfach verwenden.

## Eine Komponente erzeugen lassen

Die CLI nimmt dir die Schreibarbeit ab. Im Terminal deines Projekts:

```bash
ng generate component begruessung
```

Kurzform: `ng g c begruessung`. Es entsteht ein neuer Ordner mit vier Dateien:

```text
src/app/begruessung/
  begruessung.ts        die Klasse
  begruessung.html      das Template
  begruessung.css       die Styles
  begruessung.spec.ts   Tests
```

Die erzeugte Klasse sieht so aus:

```ts ng
import { Component } from '@angular/core';

@Component({
  imports: [],
  selector: 'app-begruessung',
  styleUrl: './begruessung.css',
  templateUrl: './begruessung.html',
})
export class Begruessung {}
```

Der Selektor ist `app-begruessung`. Die Vorsilbe `app-` setzt die CLI automatisch davor, damit sich eigene Komponenten nicht mit echten HTML-Elementen verwechseln lassen.

> [!NOTE] Namen mit mehreren Wörtern
> Im Befehl schreibst du mehrere Wörter mit Bindestrich: `ng g c todo-liste`. Daraus werden der Ordner `todo-liste`, die Datei `todo-liste.ts`, der Selektor `app-todo-liste` und die Klasse `TodoListe`.

## Eine Komponente verwenden

Damit `App` die neue Komponente anzeigen kann, braucht es **zwei Schritte**:

**1. Importieren und eintragen** – in `app.ts`:

```ts nocheck
import { Component } from '@angular/core';
import { Begruessung } from './begruessung/begruessung';

@Component({
  selector: 'app-root',
  imports: [Begruessung],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
```

Die `import`-Zeile oben ist normales TypeScript: Sie macht die Klasse in dieser Datei bekannt. Der Eintrag im Array `imports` des Decorators sagt Angular zusätzlich: «Im Template dieser Komponente darf `<app-begruessung>` vorkommen.»

**2. Im Template einsetzen** – in `app.html`:

```html
<h1>Meine App</h1>
<app-begruessung />
<app-begruessung />
```

Jedes `<app-begruessung />` erzeugt eine **eigene Instanz** der Komponente, mit eigenen Daten. Hätte die Komponente einen Zähler, würden die beiden unabhängig voneinander zählen.

> [!WARN] Die häufigste Fehlermeldung bei Komponenten
> *«'app-begruessung' is not a known element»* bedeutet fast immer: Die Komponente fehlt im `imports`-Array der Komponente, in deren Template sie benutzt wird. In VS Code hilft [[Strg]] + [[.]] auf dem rot markierten Element – die Erweiterung «Angular Language Service» bietet an, den Import einzufügen.

## Wie schneidet man eine App in Komponenten?

Eine gute Komponente hat **eine** Aufgabe. Anhaltspunkte für eine eigene Komponente:

- Etwas kommt **mehrfach** vor (jede Karte in einer Liste).
- Ein Teil der Seite ist **in sich abgeschlossen** (Kopfzeile, Suchfeld, Formular).
- Eine Datei wird **zu lang** und unübersichtlich.

=== inputs | Daten an Komponenten übergeben: input() | 20
Eine Komponente, die immer dasselbe anzeigt, ist wenig nützlich. Eine Produktkarte soll jedes Mal ein anderes Produkt zeigen. Dafür bekommt die Komponente Daten **von aussen** – von der Komponente, die sie verwendet. Man spricht von Eltern- und Kindkomponente.

## Ein Input anlegen

In der Kindkomponente legst du mit `input()` fest, welche Daten sie annimmt:

```ts ng
import { Component, input } from '@angular/core';

@Component({
  selector: 'app-karte',
  template: `
    <h3>{{ titel() }}</h3>
    <p>{{ preis() }} Franken</p>
  `,
})
export class Karte {
  readonly titel = input.required<string>();
  readonly preis = input(0);
}
```

Es gibt zwei Varianten:

- `input.required<string>()` – ein **Pflicht-Input**. Wer die Komponente verwendet, muss einen Wert übergeben, sonst gibt es einen Fehler. Der Typ steht in spitzen Klammern.
- `input(0)` – ein **optionaler Input** mit Standardwert. Wird nichts übergeben, gilt die `0`. Den Typ erkennt TypeScript am Standardwert.

Ein Input ist ein Signal. Du liest ihn wie gewohnt mit Klammern: `titel()`. Ändern kann ihn die Kindkomponente nicht – er gehört der Elternkomponente.

## Einen Input befüllen

Die Elternkomponente übergibt die Werte mit eckigen Klammern – das ist Property Binding, genau wie bei `[disabled]`:

```html
<app-karte [titel]="'Rucksack'" [preis]="45" />
<app-karte [titel]="produktName()" />
```

Achte beim ersten Beispiel auf die doppelten Anführungszeichen: `[titel]="'Rucksack'"`. Zwischen den äusseren steht ein Ausdruck, und ein fester Text braucht darin seine eigenen (einfachen) Anführungszeichen. Für festen Text geht es auch einfacher, ohne eckige Klammern: `titel="Rucksack"`.

## Zusammen mit @for

Der typische Fall: eine Liste von Daten, für jedes Element eine Komponente.

```html
@for (produkt of produkte(); track produkt.id) {
  <app-karte [titel]="produkt.name" [preis]="produkt.preis" />
}
```

## Ganze Objekte übergeben

Statt jede Eigenschaft einzeln kannst du auch das ganze Objekt übergeben. Dafür legst du das Interface in eine eigene Datei, damit beide Komponenten es importieren können:

```ts title=produkt.ts
export interface Produkt {
  id: number;
  name: string;
  preis: number;
}
```

```ts nocheck title=karte/karte.ts
import { Component, input } from '@angular/core';
import { Produkt } from '../produkt';

@Component({
  selector: 'app-karte',
  template: `<h3>{{ produkt().name }}</h3>`,
})
export class Karte {
  readonly produkt = input.required<Produkt>();
}
```

Im Template der Elternkomponente: `<app-karte [produkt]="produkt" />`.

Beachte den Pfad `'../produkt'`: Die Karte liegt im Unterordner `karte`, das Interface einen Ordner weiter oben.

## Abgeleitete Werte

Weil Inputs Signale sind, funktionieren sie mit `computed`:

```ts ng
import { Component, computed, input } from '@angular/core';

@Component({
  selector: 'app-preis',
  template: `<span [class.teuer]="istTeuer()">{{ betrag() }} Franken</span>`,
})
export class Preis {
  readonly betrag = input.required<number>();
  readonly istTeuer = computed(() => this.betrag() > 100);
}
```

> [!NOTE] Älterer Code: @Input()
> Früher schrieb man `@Input() titel = '';` mit einem Decorator. Das war kein Signal und wurde ohne Klammern gelesen. In neuem Code verwendest du `input()`.

=== outputs | Ereignisse nach oben melden: output() | 20
Daten fliessen von der Eltern- zur Kindkomponente. Aber was, wenn in der Kindkomponente etwas passiert, wovon die Elternkomponente wissen muss – etwa ein Klick auf «Löschen»?

Die Kindkomponente darf die Daten der Eltern nicht selbst ändern. Stattdessen **meldet** sie ein Ereignis, und die Elternkomponente entscheidet, was geschieht.

## Ein Output anlegen

```ts ng
import { Component, input, output } from '@angular/core';

@Component({
  selector: 'app-eintrag',
  template: `
    <span>{{ titel() }}</span>
    <button (click)="loeschen.emit()">Löschen</button>
  `,
})
export class Eintrag {
  readonly titel = input.required<string>();
  readonly loeschen = output<void>();
}
```

`output<void>()` legt ein Ereignis ohne mitgeschickten Wert an. Mit `loeschen.emit()` wird es ausgelöst («emit» = aussenden).

## Auf einen Output reagieren

Die Elternkomponente hört mit runden Klammern zu – genau wie bei `(click)`:

```html
<app-eintrag [titel]="aufgabe.titel" (loeschen)="entferne(aufgabe.id)" />
```

Dein eigenes Ereignis `loeschen` verhält sich wie ein eingebautes Ereignis. Die Kindkomponente weiss nichts von der Liste oder von `entferne` – sie meldet nur: «Jemand will mich löschen.»

## Einen Wert mitschicken

Ein Output kann einen Wert transportieren. Den Typ gibst du in spitzen Klammern an:

```ts ng
import { Component, output } from '@angular/core';

@Component({
  selector: 'app-farbwahl',
  template: `
    <button (click)="gewaehlt.emit('rot')">Rot</button>
    <button (click)="gewaehlt.emit('blau')">Blau</button>
  `,
})
export class Farbwahl {
  readonly gewaehlt = output<string>();
}
```

In der Elternkomponente steht der mitgeschickte Wert in der besonderen Variable `$event`:

```html
<app-farbwahl (gewaehlt)="farbe.set($event)" />
<p>Gewählt: {{ farbe() }}</p>
```

## Das Zusammenspiel

| Richtung | In der Kindkomponente | In der Elternkomponente |
| --- | --- | --- |
| Daten hinein | `name = input<string>()` | `[name]="wert()"` |
| Ereignis heraus | `geklickt = output<number>()` | `(geklickt)="methode($event)"` |

> [!MERKE] Daten runter, Ereignisse rauf
> Die Elternkomponente besitzt die Daten. Kinder bekommen sie über Inputs und melden Wünsche über Outputs. So gibt es für jede Information genau einen Ort, an dem sie geändert wird – und Fehler lassen sich leicht finden.

Benenne Outputs nach dem, was passiert ist (`geloescht`, `gewaehlt`, `gespeichert`) oder was gewünscht wird (`loeschen`, `schliessen`). Vermeide Namen eingebauter Ereignisse wie `click` oder `change`.

=== services | Services: Daten und Logik teilen | 25
Inputs und Outputs verbinden Eltern und Kinder. Aber was, wenn zwei Komponenten an ganz verschiedenen Stellen der App dieselben Daten brauchen – etwa der Warenkorb in der Kopfzeile und auf der Produktseite?

Die Daten durch viele Ebenen hindurchzureichen, wäre mühsam. Die Lösung ist ein **Service**: eine Klasse ausserhalb der Komponenten, die Daten und Logik für die ganze App bereithält.

## Einen Service schreiben

Erzeugen lässt er sich mit der CLI:

```bash
ng generate service warenkorb
```

Ein Service ist eine gewöhnliche Klasse mit dem Decorator `@Service()`:

```ts ng
import { Service, computed, signal } from '@angular/core';

@Service()
export class Warenkorb {
  private readonly artikel = signal<string[]>([]);

  readonly liste = this.artikel.asReadonly();
  readonly anzahl = computed(() => this.artikel().length);

  hinzufuegen(name: string): void {
    this.artikel.update((alt) => [...alt, name]);
  }

  leeren(): void {
    this.artikel.set([]);
  }
}
```

Hier siehst du Kapselung in Aktion, wie du sie bei den Klassen gelernt hast:

- Das schreibbare Signal `artikel` ist `private`. Von aussen kann niemand `set` oder `update` aufrufen.
- `asReadonly()` gibt eine **nur lesbare** Sicht auf dasselbe Signal heraus. Komponenten können die Liste anzeigen, aber nicht verändern.
- Änderungen gehen ausschliesslich über die Methoden `hinzufuegen` und `leeren`.

## Einen Service verwenden: inject()

Eine Komponente holt sich den Service mit `inject`:

```ts nocheck
import { Component, inject } from '@angular/core';
import { Warenkorb } from './warenkorb';

@Component({
  selector: 'app-kopfzeile',
  template: `<p>Im Warenkorb: {{ warenkorb.anzahl() }}</p>`,
})
export class Kopfzeile {
  protected readonly warenkorb = inject(Warenkorb);
}
```

Du schreibst **nicht** `new Warenkorb()`. `inject(Warenkorb)` bittet Angular: «Gib mir den Warenkorb.» Angular erzeugt beim ersten Mal ein Objekt und gibt danach **immer dasselbe** zurück – an jede Komponente, die danach fragt.

Das ist der entscheidende Punkt: Alle Komponenten teilen sich ein und dieselbe Instanz. Fügt die Produktseite einen Artikel hinzu, aktualisiert sich die Zahl in der Kopfzeile automatisch, weil beide dasselbe Signal lesen.

Dieses Prinzip heisst **Dependency Injection** («Abhängigkeiten hineinreichen»). Du musst dir nur merken: Services bekommt man mit `inject(...)`, nie mit `new`.

## Was gehört in einen Service?

- **Daten, die mehrere Komponenten brauchen** (Warenkorb, angemeldeter Benutzer, Aufgabenliste).
- **Logik, die nichts mit der Anzeige zu tun hat** (rechnen, speichern, Daten vom Server holen).

Komponenten bleiben dadurch schlank: Sie zeigen an und leiten Klicks weiter. Die eigentliche Arbeit macht der Service.

> [!NOTE] Älterer Code
> In älteren Projekten steht statt `@Service()` der Decorator `@Injectable({ providedIn: 'root' })`, und der Service wird über den Constructor geholt: `constructor(private warenkorb: Warenkorb) {}`. Das bedeutet dasselbe. Du erkennst darin die Kurzschreibweise für Constructor-Parameter aus der Lektion über Sichtbarkeit wieder.

=== formulare | Formulare | 25
Für einzelne Eingabefelder reicht die Technik mit `#feld`. Sobald ein Formular mehrere Felder hat und Eingaben geprüft werden sollen, nimmst du Angulars **Signal Forms**. Die Idee: Die Daten des Formulars liegen in einem Signal, und Angular verbindet es in beide Richtungen mit den Feldern.

## Schritt 1: Das Datenmodell

```ts ng
import { Component, signal } from '@angular/core';

@Component({ selector: 'app-anmeldung', template: '' })
export class Anmeldung {
  readonly daten = signal({ name: '', email: '', alter: 0 });
}
```

Ein gewöhnliches Signal mit einem Objekt. Jede Eigenschaft entspricht einem Feld.

## Schritt 2: Daraus ein Formular machen

```ts ng
import { Component, signal } from '@angular/core';
import { form, FormField } from '@angular/forms/signals';

@Component({
  selector: 'app-anmeldung',
  imports: [FormField],
  templateUrl: './anmeldung.html',
})
export class Anmeldung {
  readonly daten = signal({ name: '', email: '', alter: 0 });
  readonly formular = form(this.daten);
}
```

`form(this.daten)` baut um das Signal herum ein Formular. Für jede Eigenschaft gibt es darin ein **Feld**: `formular.name`, `formular.email`, `formular.alter`. `FormField` muss ins `imports`-Array, damit das Template die Felder verbinden kann.

## Schritt 3: Die Felder im Template verbinden

```html
<label>Name <input type="text" [formField]="formular.name" /></label>
<label>E-Mail <input type="email" [formField]="formular.email" /></label>
<label>Alter <input type="number" [formField]="formular.alter" /></label>

<p>Hallo {{ daten().name }}!</p>
```

`[formField]="formular.name"` verbindet das Eingabefeld **in beide Richtungen** mit `daten().name`: Tippt der Benutzer, ändert sich das Signal. Ändert sich das Signal, ändert sich das Feld. Du brauchst weder `#feld` noch `(input)`.

Beim Zahlenfeld bekommst du sogar automatisch eine `number` statt eines Texts.

## Schritt 4: Eingaben prüfen

Als zweites Argument übergibst du `form` eine Funktion mit Regeln:

```ts ng
import { Component, signal } from '@angular/core';
import { form, FormField, required, minLength, email, min } from '@angular/forms/signals';

@Component({
  selector: 'app-anmeldung',
  imports: [FormField],
  templateUrl: './anmeldung.html',
})
export class Anmeldung {
  readonly daten = signal({ name: '', email: '', alter: 0 });

  readonly formular = form(this.daten, (pfad) => {
    required(pfad.name, { message: 'Bitte gib deinen Namen an.' });
    minLength(pfad.name, 2, { message: 'Mindestens 2 Zeichen.' });
    email(pfad.email, { message: 'Das ist keine gültige E-Mail-Adresse.' });
    min(pfad.alter, 12, { message: 'Du musst mindestens 12 sein.' });
  });
}
```

Jede Regel bekommt den Pfad zum Feld und – freiwillig – eine Meldung. Die wichtigsten Regeln:

| Regel | Prüft |
| --- | --- |
| `required(pfad.x)` | Feld darf nicht leer sein |
| `minLength(pfad.x, n)` / `maxLength(pfad.x, n)` | Länge des Texts |
| `min(pfad.x, n)` / `max(pfad.x, n)` | Grösse der Zahl |
| `email(pfad.x)` | sieht aus wie eine E-Mail-Adresse |
| `pattern(pfad.x, /.../)` | passt auf ein Muster |

## Schritt 5: Den Zustand anzeigen

Ein Feld ist selbst ein Signal. Rufst du es auf, bekommst du seinen **Zustand** – mit weiteren Signalen:

| Ausdruck | Bedeutung |
| --- | --- |
| `formular.name().valid()` | alle Regeln erfüllt? |
| `formular.name().invalid()` | mindestens eine Regel verletzt? |
| `formular.name().touched()` | hat der Benutzer das Feld schon besucht? |
| `formular.name().errors()` | Liste der Fehler, jeder mit `message` |
| `formular().valid()` | ist das **ganze** Formular gültig? |

Achte auf die Klammern: `formular.name` ist das Feld, `formular.name()` sein Zustand, `formular.name().valid()` der Wert.

```html
<label>Name <input type="text" [formField]="formular.name" /></label>

@if (formular.name().touched() && formular.name().invalid()) {
  @for (fehler of formular.name().errors(); track fehler.kind) {
    <p class="fehler">{{ fehler.message }}</p>
  }
}
```

Die Prüfung auf `touched()` sorgt dafür, dass die Meldung erst erscheint, wenn der Benutzer das Feld wieder verlassen hat – und nicht schon beim leeren Formular.

## Schritt 6: Abschicken

```html
<form (submit)="absenden($event)">
  <!-- Felder -->
  <button type="submit" [disabled]="formular().invalid()">Anmelden</button>
</form>
```

```ts nocheck
absenden(ereignis: Event): void {
  ereignis.preventDefault();
  if (this.formular().invalid()) {
    return;
  }
  console.log('Abgeschickt:', this.daten());
}
```

`ereignis.preventDefault()` verhindert, dass der Browser die Seite neu lädt – das wäre sein Standardverhalten bei Formularen. Die eingegebenen Daten liest du einfach aus dem Signal `daten()`.

> [!NOTE] Andere Formular-Arten
> In älteren Anleitungen findest du «Template-driven Forms» (mit `[(ngModel)]`) und «Reactive Forms» (mit `FormGroup` und `FormControl`). Beide funktionieren weiterhin. Signal Forms sind der neueste Weg und passen am besten zu allem, was du in diesem Kurs gelernt hast.

=== routing | Mehrere Seiten: Routing | 25
Eine Web-App hat meist mehrere Ansichten: Startseite, Detailseite, Einstellungen. In Angular lädt der Browser dabei **keine neue Seite** – Angular tauscht nur die angezeigte Komponente aus und passt die Adresse an. Das heisst **Routing**, und die App nennt man eine «Single Page Application».

## Routen festlegen

In `src/app/app.routes.ts` steht die Tabelle «Adresse → Komponente»:

```ts nocheck title=app.routes.ts
import { Routes } from '@angular/router';
import { Start } from './start/start';
import { Ueber } from './ueber/ueber';

export const routes: Routes = [
  { path: '', component: Start },
  { path: 'ueber', component: Ueber },
  { path: '**', redirectTo: '' },
];
```

- `path: ''` ist die Startseite (`http://localhost:4200/`).
- `path: 'ueber'` ist `http://localhost:4200/ueber`. Der Pfad steht **ohne** Schrägstrich am Anfang.
- `path: '**'` passt auf alles, was sonst nicht passt, und leitet hier zur Startseite um. Diese Route steht immer zuletzt.

## Wo die Seite erscheint: router-outlet

Im Template der Wurzelkomponente markierst du die Stelle, an der die jeweilige Seite angezeigt wird:

```html title=app.html
<nav>
  <a routerLink="/">Start</a>
  <a routerLink="/ueber">Über uns</a>
</nav>

<router-outlet />
```

Alles ausserhalb von `<router-outlet />` – hier die Navigation – bleibt auf jeder Seite stehen.

## Links: routerLink statt href

Für Links innerhalb der App nimmst du `routerLink`. Ein gewöhnliches `href` würde die ganze Seite neu laden und alle Daten in deinen Signals wären weg.

Damit das Template `routerLink` und `<router-outlet>` kennt, müssen sie ins `imports`-Array:

```ts nocheck title=app.ts
import { Component } from '@angular/core';
import { RouterLink, RouterLinkActive, RouterOutlet } from '@angular/router';

@Component({
  selector: 'app-root',
  imports: [RouterOutlet, RouterLink, RouterLinkActive],
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
```

Mit `routerLinkActive` bekommt der Link der aktuellen Seite automatisch eine CSS-Klasse:

```html
<a routerLink="/ueber" routerLinkActive="aktiv">Über uns</a>
```

## Seiten mit Parametern

Eine Detailseite soll je nach Adresse etwas anderes zeigen: `/buch/1`, `/buch/2`. Dafür gibt es Platzhalter mit Doppelpunkt:

```ts nocheck
{ path: 'buch/:id', component: BuchDetail },
```

Am bequemsten kommt der Wert als **Input** in der Komponente an. Dazu wird das einmalig in `app.config.ts` eingeschaltet:

```ts nocheck title=app.config.ts
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes, withComponentInputBinding()),
  ],
};
```

Danach genügt in der Komponente ein Input mit **demselben Namen** wie der Platzhalter:

```ts ng
import { Component, input } from '@angular/core';

@Component({
  selector: 'app-buch-detail',
  template: `<h1>Buch Nummer {{ id() }}</h1>`,
})
export class BuchDetail {
  readonly id = input.required<string>();
}
```

Parameter aus der Adresse sind immer **Strings**. Brauchst du eine Zahl, wandelst du um: `Number(this.id())`.

Links mit Parameter baust du mit einem Array aus den Teilen der Adresse:

```html
@for (buch of buecher(); track buch.id) {
  <a [routerLink]="['/buch', buch.id]">{{ buch.titel }}</a>
}
```

Manchmal soll nach einer Aktion automatisch die Seite wechseln, etwa nach dem Speichern. Dafür holst du dir den `Router`:

```ts nocheck

export class Formular {
  private readonly router = inject(Router);

  speichern(): void {
    // ... speichern ...
    this.router.navigate(['/']);
  }
}
```

`Router` ist ein Service, der von Angular mitgeliefert wird – und du holst ihn mit `inject`, wie deine eigenen.

=== http | Daten aus dem Internet laden | 25
Die meisten Apps zeigen Daten, die von einem Server kommen. Der Server stellt sie über eine **API** bereit: eine Adresse, die statt einer Webseite reine Daten liefert, fast immer im Format **JSON**.

JSON sieht aus wie Objekte und Arrays in TypeScript – nur dass alle Namen in doppelten Anführungszeichen stehen:

```json
[
  { "id": 1, "name": "Leanne Graham", "email": "leanne@example.com" },
  { "id": 2, "name": "Ervin Howell", "email": "ervin@example.com" }
]
```

Zum Üben gibt es öffentliche Test-APIs. In dieser Lektion verwenden wir `https://jsonplaceholder.typicode.com/users` – sie liefert zehn erfundene Benutzer. Öffne die Adresse ruhig einmal im Browser.

## Vorbereitung: HTTP einschalten

Einmalig in `app.config.ts`:

```ts nocheck title=app.config.ts
import { ApplicationConfig, provideBrowserGlobalErrorListeners } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideRouter(routes),
    provideHttpClient(),
  ],
};
```

## Daten laden mit httpResource

```ts ng
import { Component } from '@angular/core';
import { httpResource } from '@angular/common/http';

interface Benutzer {
  id: number;
  name: string;
  email: string;
}

@Component({
  selector: 'app-benutzer',
  templateUrl: './benutzer.html',
})
export class BenutzerListe {
  readonly benutzer = httpResource<Benutzer[]>(() => 'https://jsonplaceholder.typicode.com/users');
}
```

`httpResource` bekommt eine Funktion, die die Adresse liefert, und in spitzen Klammern den Typ der erwarteten Daten. Es startet die Anfrage von selbst und stellt das Ergebnis als Signale bereit:

| Signal | Bedeutung |
| --- | --- |
| `benutzer.isLoading()` | läuft die Anfrage gerade? |
| `benutzer.error()` | der Fehler, falls etwas schiefging |
| `benutzer.value()` | die Daten – oder `undefined`, solange keine da sind |
| `benutzer.hasValue()` | sind Daten da? |

## Die drei Zustände anzeigen

Erinnerst du dich an das Dreierpaket «Laden, Erfolg, Fehler» aus der Lektion über Fehlerbehandlung? Hier ist es wieder – diesmal im Template:

```html
@if (benutzer.isLoading()) {
  <p>Daten werden geladen …</p>
} @else if (benutzer.error()) {
  <p>Die Daten konnten nicht geladen werden.</p>
  <button (click)="benutzer.reload()">Nochmal versuchen</button>
} @else {
  <ul>
    @for (person of benutzer.value(); track person.id) {
      <li>{{ person.name }} – {{ person.email }}</li>
    }
  </ul>
}
```

Eine App, die während des Ladens nichts anzeigt oder bei einem Fehler einfach leer bleibt, wirkt kaputt. Behandle immer alle drei Fälle.

## Die Adresse hängt von einem Signal ab

Weil die Adresse aus einer Funktion kommt, darf sie Signale lesen. Ändert sich das Signal, lädt `httpResource` **automatisch neu**:

```ts ng
import { Component, signal } from '@angular/core';
import { httpResource } from '@angular/common/http';

interface Benutzer {
  id: number;
  name: string;
}

@Component({ selector: 'app-profil', template: '' })
export class Profil {
  readonly id = signal(1);
  readonly person = httpResource<Benutzer>(() => `https://jsonplaceholder.typicode.com/users/${this.id()}`);

  naechster(): void {
    this.id.update((alt) => alt + 1);
  }
}
```

Ein Klick auf «Nächster» ändert nur `id` – das Laden passiert von selbst.

> [!WARN] Der Typ ist ein Versprechen, keine Prüfung
> `httpResource<Benutzer[]>` sagt TypeScript: «Vertrau mir, da kommen Benutzer.» Ob der Server wirklich solche Daten schickt, prüft niemand – Typen gibt es im laufenden Programm ja nicht. Schau dir die Antwort der API deshalb immer zuerst im Browser an und schreibe dein Interface danach.

## Daten senden

Zum Speichern, Ändern und Löschen auf einem Server gibt es den Service `HttpClient` mit den Methoden `post`, `put` und `delete`. Er arbeitet mit sogenannten Observables, einer weiteren Art, mit Asynchronem umzugehen. Das führt über diesen Kurs hinaus – die Anleitung dazu findest du auf [angular.dev](https://angular.dev/guide/http).

=== pipes-styling | Werte formatieren und gestalten | 20
Zwei Themen, die deine App ansehnlich machen: **Pipes** bringen Werte in eine lesbare Form, und mit **CSS** gestaltest du deine Komponenten.

## Pipes

Eine Pipe formatiert einen Wert direkt im Template. Sie steht hinter einem senkrechten Strich:

```html
<p>{{ name() | uppercase }}</p>
<p>{{ heute | date: 'dd.MM.yyyy' }}</p>
<p>{{ preis() | currency: 'CHF' }}</p>
<p>{{ anteil() | percent }}</p>
<p>{{ durchschnitt() | number: '1.1-2' }}</p>
```

Hinter dem Doppelpunkt stehen Einstellungen. Die Daten selbst bleiben unverändert – nur die Anzeige ändert sich.

| Pipe | Beispiel | Ergebnis |
| --- | --- | --- |
| `uppercase` / `lowercase` | `'Hallo' \| uppercase` | `HALLO` |
| `titlecase` | `'guten tag' \| titlecase` | `Guten Tag` |
| `date` | `datum \| date: 'dd.MM.yyyy'` | `09.11.2026` |
| `date` | `datum \| date: 'HH:mm'` | `14:05` |
| `number` | `3.14159 \| number: '1.0-2'` | `3.14` |
| `currency` | `12.5 \| currency: 'CHF'` | `CHF12.50` |
| `percent` | `0.25 \| percent` | `25%` |
| `json` | `objekt \| json` | das Objekt als Text – praktisch zum Nachschauen |

Die Angabe bei `number` bedeutet `'mindestStellenVorKomma.minNachkomma-maxNachkomma'`. `'1.0-2'` heisst also: mindestens eine Stelle vor dem Komma, null bis zwei danach.

Jede Pipe, die du verwendest, muss ins `imports`-Array der Komponente:

```ts ng
import { Component, signal } from '@angular/core';
import { CurrencyPipe, DatePipe, UpperCasePipe } from '@angular/common';

@Component({
  selector: 'app-beleg',
  imports: [CurrencyPipe, DatePipe, UpperCasePipe],
  template: `
    <h2>{{ laden | uppercase }}</h2>
    <p>{{ datum | date: 'dd.MM.yyyy' }}</p>
    <p>{{ betrag() | currency: 'CHF' }}</p>
  `,
})
export class Beleg {
  readonly laden = 'Kiosk';
  readonly datum = new Date();
  readonly betrag = signal(12.5);
}
```

Die Klassen heissen wie die Pipe plus `Pipe`: `DatePipe`, `CurrencyPipe`, `DecimalPipe` (für `number`), `PercentPipe`, `UpperCasePipe`, `LowerCasePipe`, `TitleCasePipe`, `JsonPipe`.

> [!TIP] json zum Nachschauen
> `<pre>{{ daten() | json }}</pre>` zeigt ein beliebiges Objekt direkt auf der Seite an. Das ist das `console.log` für Templates – ideal, um schnell zu prüfen, was in einem Signal wirklich steckt.

## Styles pro Komponente

Jede Komponente hat ihre eigene CSS-Datei. Das Besondere: Diese Styles gelten **nur für diese Komponente**.

```css
h2 {
  color: darkblue;
}

.karte {
  border: 1px solid lightgray;
  border-radius: 8px;
  padding: 16px;
}
```

Das `h2` in `karte.css` färbt nur Überschriften im Template der Karte – nicht die in anderen Komponenten. Du kannst also überall einfache Klassennamen wie `.titel` oder `.liste` verwenden, ohne dass sie sich in die Quere kommen.

## Styles für die ganze App

Was überall gelten soll – Schriftart, Grundfarben, Abstände der Seite –, gehört in `src/styles.css`:

```css
body {
  font-family: system-ui, sans-serif;
  margin: 0;
  padding: 24px;
  max-width: 640px;
}

button {
  font: inherit;
  padding: 6px 12px;
}
```

## Die Komponente selbst gestalten

Das Element einer Komponente (`<app-karte>`) ist für den Browser zunächst ein Element ohne Eigenschaften. Mit `:host` sprichst du es in der CSS-Datei der Komponente an:

```css
:host {
  display: block;
  margin-bottom: 12px;
}
```

`display: block` sorgt dafür, dass sich die Komponente wie ein Absatz oder ein `<div>` verhält und Abstände wirken.
