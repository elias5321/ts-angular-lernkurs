#part typen | TypeScript richtig nutzen: Typen | Jetzt kommt das, was TypeScript von JavaScript unterscheidet: eigene Typen, Varianten, fehlende Werte und Generics. Dieses Wissen brauchst du in Angular jeden Tag.

=== interfaces | Eigene Typen: interface und type | 20
In der letzten Lektion hast du Objekt-Typen direkt hingeschrieben: `{ titel: string; seiten: number }`. Sobald derselbe Typ an mehreren Stellen vorkommt, wird das mühsam. Die Lösung: Gib dem Typ einen **Namen**.

## interface

```ts
interface Buch {
  titel: string;
  autor: string;
  seiten: number;
}

const momo: Buch = {
  titel: "Momo",
  autor: "Michael Ende",
  seiten: 304,
};

function beschreibe(buch: Buch): string {
  return `${buch.titel} von ${buch.autor}`;
}

console.log(beschreibe(momo));
```

Ein `interface` beschreibt die **Form** eines Objekts: welche Eigenschaften es hat und welche Typen sie haben. Der Name beginnt mit einem Grossbuchstaben (`Buch`, `Benutzer`, `TodoEintrag`).

Ab jetzt ist `Buch` ein Typ wie `string` oder `number`. Du kannst ihn überall verwenden: bei Variablen, Parametern, Rückgabewerten und in Arrays (`Buch[]`).

## TypeScript prüft die Form

Ein Objekt vom Typ `Buch` muss **alle** Eigenschaften haben, mit den **richtigen Typen**, und **keine zusätzlichen**:

```ts error
interface Buch {
  titel: string;
  autor: string;
  seiten: number;
}

const a: Buch = { titel: "Momo", autor: "Michael Ende" };              // seiten fehlt
const b: Buch = { titel: "Momo", autor: "Michael Ende", seiten: "304" }; // falscher Typ
const c: Buch = { titel: "Momo", autor: "Michael Ende", seiten: 304, preis: 12 }; // preis gibt es nicht
```

> [!MERKE] Ein Interface existiert nur beim Prüfen
> Ein `interface` erzeugt keinen Code. Beim Übersetzen nach JavaScript verschwindet es spurlos. Es ist eine reine Beschreibung für TypeScript und für dich.

## type

Es gibt eine zweite Möglichkeit, einem Typ einen Namen zu geben – das Schlüsselwort `type`:

```ts
type Punkt = {
  x: number;
  y: number;
};

const start: Punkt = { x: 0, y: 0 };
console.log(start);
```

Beachte das Gleichheitszeichen: `type Name = ...`. Bei `interface` steht keines.

## interface oder type?

Für Objekte sind beide fast gleichwertig. `type` kann aber mehr: Damit lassen sich auch Typen benennen, die **keine** Objekte sind – das brauchst du in der übernächsten Lektion.

Eine verbreitete Faustregel, an die sich auch dieser Kurs hält:

- **`interface`** für die Form von Objekten (Daten wie `Buch`, `Benutzer`).
- **`type`** für alles andere (Varianten, Kombinationen, Funktionstypen).

## Interfaces verschachteln

Eigenschaften können selbst wieder Interfaces oder Arrays sein:

```ts
interface Adresse {
  strasse: string;
  ort: string;
}

interface Schueler {
  name: string;
  adresse: Adresse;
  noten: number[];
}

const lena: Schueler = {
  name: "Lena",
  adresse: { strasse: "Hauptstrasse 5", ort: "Luzern" },
  noten: [5, 4.5, 6],
};

console.log(lena.adresse.ort); // "Luzern"
```

  name: string;

  return produkt.lager > 0;

=== optional-readonly | Optionale und schreibgeschützte Eigenschaften | 15
Nicht jede Angabe ist immer vorhanden. Und manche Angaben sollen sich nie ändern. Beides kannst du im Interface ausdrücken.

## Optionale Eigenschaften

Ein Fragezeichen hinter dem Namen macht eine Eigenschaft freiwillig:

```ts
interface Benutzer {
  name: string;
  email: string;
  telefon?: string;
}

const mia: Benutzer = { name: "Mia", email: "mia@example.com" };
const noah: Benutzer = { name: "Noah", email: "noah@example.com", telefon: "079 123 45 67" };

console.log(mia.telefon);  // undefined
console.log(noah.telefon); // "079 123 45 67"
```

Fehlt eine optionale Eigenschaft, hat sie den Wert `undefined`. TypeScript weiss das und gibt `telefon` den Typ `string | undefined` – «String oder nicht vorhanden». Deshalb darfst du nicht einfach damit weiterarbeiten:

```ts error
interface Benutzer {
  name: string;
  telefon?: string;
}

function telefonLaenge(benutzer: Benutzer): number {
  return benutzer.telefon.length;
}
```

Du musst zuerst prüfen, ob etwas da ist:

```ts
interface Benutzer {
  name: string;
  telefon?: string;
}

function kontakt(benutzer: Benutzer): string {
  if (benutzer.telefon) {
    return `${benutzer.name}: ${benutzer.telefon}`;
  }
  return `${benutzer.name}: keine Telefonnummer`;
}

console.log(kontakt({ name: "Mia" }));
```

Innerhalb des `if` weiss TypeScript: Hier ist `telefon` sicher ein `string`. Dieses «Mitdenken» heisst **Narrowing** (Einengen) – dazu gibt es bald eine eigene Lektion.

## readonly

Mit `readonly` vor dem Namen darf eine Eigenschaft nach dem Erstellen nicht mehr verändert werden:

```ts error
interface Benutzer {
  readonly id: number;
  name: string;
}

const mia: Benutzer = { id: 1, name: "Mia" };
mia.name = "Mia Keller"; // erlaubt
mia.id = 2;              // Fehler: id ist readonly
```

Typisch ist das für Kennungen (`id`), die ein Objekt eindeutig identifizieren. In Angular siehst du `readonly` ausserdem sehr oft bei Eigenschaften von Komponenten.

=== union-typen | Entweder-oder: Union-Typen | 20
Manchmal kann ein Wert mehrere Typen haben: eine ID ist bei manchen Systemen eine Zahl, bei anderen ein Text. Oder ein Wert darf nur aus einer kleinen, festen Auswahl stammen. Dafür gibt es **Union-Typen**.

## Mehrere Typen erlauben

Der senkrechte Strich `|` bedeutet «oder»:

```ts
let id: string | number;

id = 42;      // erlaubt
id = "abc42"; // auch erlaubt
console.log(id);
```

`boolean` wäre hier ein Fehler – es kommt in der Auswahl nicht vor.

## Feste Werte als Typ

Jetzt wird es interessant. In TypeScript kann auch ein **einzelner fester Wert** ein Typ sein. Kombiniert mit `|` entsteht eine Auswahlliste:

```ts
let ampel: "rot" | "gelb" | "grün";

ampel = "rot";  // erlaubt
ampel = "grün"; // erlaubt
console.log(ampel);
```

Alles andere wird abgelehnt – auch Tippfehler:

```ts error
let ampel: "rot" | "gelb" | "grün";
ampel = "blau";
ampel = "Rot";
```

Das ist enorm praktisch. Statt irgendeinen `string` zu erlauben, erlaubst du genau die Werte, die Sinn ergeben. VS Code schlägt sie dir beim Tippen sogar vor.

## Einen Namen geben mit type

Hier kommt `type` zum Einsatz, denn das ist kein Objekt-Typ:

```ts
type Ampelfarbe = "rot" | "gelb" | "grün";
type Schulnote = 1 | 2 | 3 | 4 | 5 | 6;

function darfFahren(farbe: Ampelfarbe): boolean {
  return farbe === "grün";
}

const meineNote: Schulnote = 5;
console.log(darfFahren("rot"), meineNote);
```

## In Interfaces verwenden

```ts
interface Aufgabe {
  titel: string;
  status: "offen" | "in Arbeit" | "erledigt";
  prioritaet: 1 | 2 | 3;
}

const hausaufgabe: Aufgabe = {
  titel: "Mathe S. 42",
  status: "offen",
  prioritaet: 2,
};
console.log(hausaufgabe);
```

Solche Status-Felder gibt es in praktisch jeder App.

> [!NOTE] Und enum?
> In anderen Sprachen und in älterem TypeScript-Code löst man das mit `enum`. TypeScript hat `enum` auch, aber heute nimmt man meistens die Union aus festen Werten: Sie ist einfacher, erzeugt keinen zusätzlichen Code und funktioniert überall. Du solltest `enum` wiedererkennen, wenn du es siehst – selbst schreiben musst du es selten.

=== narrowing | Narrowing: Typen eingrenzen | 20
Wenn ein Wert `string | number` sein kann, was darfst du dann mit ihm tun? Nur das, was mit **beiden** Typen funktioniert. Und das ist nicht viel:

```ts error
function verdopple(wert: string | number): number {
  return wert * 2;
}
```

Mit einem Text kann man nicht multiplizieren, also lehnt TypeScript das ab. Du musst zuerst herausfinden, was du vor dir hast. Dieses Herausfinden heisst **Narrowing** (Eingrenzen).

## Narrowing mit typeof

`typeof wert` liefert den Typ eines Werts als Text: `"string"`, `"number"`, `"boolean"` …

```ts
function verdopple(wert: string | number): number {
  if (typeof wert === "number") {
    return wert * 2;        // hier ist wert sicher eine number
  }
  return Number(wert) * 2;  // hier bleibt nur noch string übrig
}

console.log(verdopple(4), verdopple("5"));
```

Das Besondere: TypeScript **denkt mit**. Innerhalb des `if` weiss es, dass `wert` eine Zahl ist. Und danach weiss es, dass nur noch `string` übrig sein kann. Fahre in VS Code mit der Maus über `wert` an beiden Stellen – der angezeigte Typ ist jedes Mal ein anderer.

## Narrowing bei festen Werten

Bei Auswahl-Typen grenzt du mit einem Vergleich ein. Für mehrere Fälle ist `switch` oft übersichtlicher als eine lange `else if`-Kette:

```ts
type Ampelfarbe = "rot" | "gelb" | "grün";

function aktion(farbe: Ampelfarbe): string {
  switch (farbe) {
    case "rot":
      return "anhalten";
    case "gelb":
      return "bremsen";
    case "grün":
      return "fahren";
  }
}

console.log(aktion("gelb"));
```

`switch` vergleicht den Wert in den Klammern der Reihe nach mit jedem `case`. TypeScript prüft dabei, dass du **keinen Fall vergessen** hast: Löschst du `case "grün"`, bekommst du einen Fehler, weil die Funktion dann nicht mehr in jedem Fall etwas zurückgibt.

## Objekte unterscheiden

Der wichtigste Trick für grössere Programme: Gib verwandten Objekten eine gemeinsame Eigenschaft mit **unterschiedlichen festen Werten**. Daran kann TypeScript sie unterscheiden.

```ts
interface Kreis {
  art: "kreis";
  radius: number;
}

interface Rechteck {
  art: "rechteck";
  breite: number;
  hoehe: number;
}

type Form = Kreis | Rechteck;

function beschreibe(form: Form): string {
  if (form.art === "kreis") {
    return `Kreis mit Radius ${form.radius}`;
  }
  return `Rechteck ${form.breite} × ${form.hoehe}`;
}

console.log(beschreibe({ art: "kreis", radius: 2 }));
```

Nach der Prüfung `form.art === "kreis"` weiss TypeScript, dass `form` ein `Kreis` ist – und erlaubt `form.radius`. Im anderen Zweig erlaubt es `form.breite`. Dieses Muster heisst «Discriminated Union» und kommt in echtem Code ständig vor, zum Beispiel für Ladezustände: `{ status: "laedt" }`, `{ status: "fertig"; daten: ... }`, `{ status: "fehler"; meldung: string }`.

=== null-undefined | Wenn ein Wert fehlt: null und undefined | 20
Der berühmteste Fehler in JavaScript lautet: *«Cannot read properties of undefined»*. Er passiert, wenn man auf etwas zugreift, das gar nicht da ist. TypeScript kann diesen Fehler fast vollständig verhindern.

## Zwei Arten von «nichts»

- `undefined` – «noch kein Wert». Das liefert JavaScript von selbst: bei fehlenden Eigenschaften, weggelassenen Parametern oder wenn `find` nichts findet.
- `null` – «absichtlich leer». Das setzt ein Programmierer bewusst ein.

In der Praxis behandelt man beide meist gleich.

## TypeScript zwingt dich zum Prüfen

Im strengen Modus (den du in deiner `tsconfig.json` eingeschaltet hast und den Angular immer benutzt) gehört «nichts» **nicht** automatisch zu jedem Typ. Ein `string` ist immer ein String. Soll etwas fehlen dürfen, musst du es hinschreiben:

```ts
let spitzname: string | null = null;
spitzname = "Mimi";
console.log(spitzname);
```

Und bevor du so einen Wert benutzt, verlangt TypeScript eine Prüfung:

```ts error
function laenge(text: string | null): number {
  return text.length;
}
```

```ts
function laenge(text: string | null): number {
  if (text === null) {
    return 0;
  }
  return text.length; // hier ist text sicher ein string
}

console.log(laenge(null), laenge("hallo"));
```

Das ist wieder Narrowing: Nach der Prüfung auf `null` bleibt nur `string` übrig.

## Wo undefined herkommt

Am häufigsten begegnet dir `undefined` bei `find`. Es kann ja sein, dass nichts gefunden wird:

```ts
const namen = ["Mia", "Noah"];
const gefunden = namen.find((name) => name.startsWith("X"));
// gefunden hat den Typ: string | undefined

if (gefunden) {
  console.log(gefunden.toUpperCase());
} else {
  console.log("Niemand gefunden");
}
```

## Zwei Abkürzungen: ?. und ??

**Optional Chaining `?.`** – «greife nur zu, wenn etwas da ist». Ist der Wert links `null` oder `undefined`, wird nicht weitergemacht und das Ergebnis ist `undefined`. Kein Absturz.

**Nullish Coalescing `??`** – «nimm den Wert links; wenn er `null` oder `undefined` ist, nimm den rechts». Damit gibst du einen Ersatzwert an.

```ts
interface Benutzer {
  name: string;
  adresse?: { ort: string };
}

const mia: Benutzer = { name: "Mia" };

console.log(mia.adresse?.ort);                // undefined – kein Absturz
console.log(mia.adresse?.ort ?? "unbekannt"); // "unbekannt"
```

Die beiden treten oft als Paar auf: `?.` für den sicheren Zugriff, `??` für den Ersatzwert. In Angular-Templates wirst du `?.` sehr häufig sehen.

> [!WARN] Das Ausrufezeichen
> Es gibt noch ein drittes Zeichen: `wert!` bedeutet «Vertrau mir, das ist nie null». Damit schaltest du die Prüfung an dieser Stelle ab. Wenn du dich irrst, stürzt das Programm ab – genau das, was TypeScript verhindern wollte. Benutze `!` nur, wenn du es wirklich besser weisst als TypeScript, und das ist selten.

=== any-unknown | any und unknown | 15
Zwei besondere Typen solltest du kennen: einen, den du möglichst **vermeidest**, und einen, der sein sicherer Ersatz ist.

## any: die Typprüfung abschalten

`any` bedeutet «irgendetwas». Mit einem Wert vom Typ `any` darfst du **alles** tun – TypeScript prüft nichts mehr:

```ts
let wert: any = "hallo";
wert = 42;
wert = true;
console.log(wert.gibtEsNicht); // kein Fehler von TypeScript – einfach undefined
```

Damit bist du wieder bei JavaScript, mit allen seinen Tücken. Schlimmer noch: `any` ist ansteckend. Was du aus einem `any`-Wert herausholst, ist wieder `any`, und so breitet sich das Loch in der Prüfung aus.

`any` hat seinen Platz, wenn man alten JavaScript-Code schrittweise umstellt. In neuem Code solltest du es nicht brauchen. Wenn du bei einem Problem denkst «Ich mach das einfach `any`», ist das fast immer ein Zeichen, dass du den richtigen Typ noch nicht gefunden hast.

> [!NOTE] Implizites any
> Im strengen Modus meldet TypeScript einen Fehler, wenn es einem Parameter keinen Typ zuordnen kann: *«Parameter implicitly has an 'any' type»*. Deshalb musst du Parameter immer mit Typ versehen. Das ist Absicht.

## unknown: «weiss ich noch nicht»

`unknown` bedeutet ebenfalls «könnte alles sein» – aber mit umgekehrter Wirkung: Mit einem `unknown`-Wert darfst du **nichts** tun, bevor du nicht geprüft hast, was es ist.

```ts error
function zeige(wert: unknown): void {
  console.log(wert.toUpperCase());
}
```

```ts
function zeige(wert: unknown): void {
  if (typeof wert === "string") {
    console.log(wert.toUpperCase()); // hier ist es sicher ein string
  } else {
    console.log("kein Text");
  }
}

zeige("hallo");
zeige(42);
```

`unknown` nimmst du für Daten, deren Form du wirklich nicht kennst: was ein Benutzer eintippt, was ein Server schickt, was beim Abfangen eines Fehlers ankommt.

> [!MERKE] Der Unterschied in einem Satz
> `any` sagt «frag nicht», `unknown` sagt «prüf zuerst».

=== funktionstypen | Funktionen als Werte | 15
In TypeScript (und JavaScript) sind Funktionen ganz normale Werte. Du kannst sie in Variablen speichern und an andere Funktionen übergeben. Das hast du schon getan: `zahlen.map((z) => z * 2)` übergibt eine Funktion an `map`.

Jetzt lernst du, wie man den **Typ einer Funktion** hinschreibt.

## Der Typ einer Funktion

```ts
let rechne: (a: number, b: number) => number;

rechne = (a, b) => a + b;
console.log(rechne(2, 3)); // 5

rechne = (a, b) => a * b;
console.log(rechne(2, 3)); // 6
```

Der Typ `(a: number, b: number) => number` liest sich: «eine Funktion, die zwei Zahlen bekommt und eine Zahl zurückgibt». Er sieht aus wie eine Pfeilfunktion, nur steht hinter dem Pfeil ein Typ statt Code.

Die Parameternamen im Typ (`a`, `b`) dienen nur der Lesbarkeit. Die echte Funktion darf ihre Parameter anders nennen.

## Mit type einen Namen geben

```ts
type Rechenart = (a: number, b: number) => number;

const plus: Rechenart = (a, b) => a + b;
const mal: Rechenart = (a, b) => a * b;

console.log(plus(4, 5), mal(4, 5));
```

## Funktionen als Parameter: Callbacks

Eine Funktion, die du an eine andere Funktion übergibst, damit diese sie später aufruft, heisst **Callback** («Rückruf»).

```ts
function wiederhole(anzahl: number, aktion: (runde: number) => void): void {
  for (let i = 1; i <= anzahl; i++) {
    aktion(i);
  }
}

wiederhole(3, (runde) => console.log(`Runde ${runde}`));
```

`wiederhole` weiss nicht, **was** getan werden soll – das bestimmt der Aufrufer. Es weiss nur, dass es die übergebene Funktion dreimal aufrufen soll. Genau so funktionieren `map`, `filter` und auch Klick-Ereignisse in Angular: «Wenn der Knopf gedrückt wird, ruf diese Funktion auf.»

--- code callback-anwenden | Eine eigene map-Funktion
Schreibe eine Funktion `wendeAn` mit zwei Parametern:

- `zahlen` – ein Array von Zahlen
- `umwandlung` – eine Funktion, die eine Zahl bekommt und eine Zahl zurückgibt

`wendeAn` ruft `umwandlung` für jede Zahl auf und gibt ein neues Array mit den Ergebnissen zurück. Benutze dafür eine `for...of`-Schleife und `push` – du baust gerade `map` nach, also verwende `map` selbst nicht.
@starter

@solution
// Schreibe hier die Funktion wendeAn
function wendeAn(zahlen: number[], umwandlung: (zahl: number) => number): number[] {
  const ergebnis: number[] = [];
  for (const zahl of zahlen) {
    ergebnis.push(umwandlung(zahl));
  }
  return ergebnis;
}

console.log(wendeAn([1, 2, 3], (zahl) => zahl * 10));
@tests

run wendeAn([1, 2, 3], (z) => z * 10).join(",") === "10,20,30" :: Mal 10: `[1, 2, 3]` wird zu `[10, 20, 30]`
run wendeAn([4, 9], Math.sqrt).join(",") === "2,3" :: Mit `Math.sqrt`: `[4, 9]` wird zu `[2, 3]`
run wendeAn([], (z) => z).length === 0 :: Ein leeres Array bleibt leer
nosrc /\.map\s*\(/ :: Ohne `map` gelöst
@hints
- Der zweite Parameter: `umwandlung: (zahl: number) => number`
- Ein leeres Array braucht eine Typangabe, sonst weiss TypeScript nicht, was hinein soll: `const ergebnis: number[] = [];`
- In der Schleife: `ergebnis.push(umwandlung(zahl));`
@after
Du hast gerade `map` selbst gebaut. Es ist keine Zauberei: eine Schleife, die für jedes Element die übergebene Funktion aufruft.

=== generics | Generics: Typen mit Platzhaltern | 20
`string[]` kennst du. Dafür gibt es eine zweite, gleichbedeutende Schreibweise: `Array<string>`. Die spitzen Klammern bedeuten: «ein Array **von** Strings». `Array` ist ein Typ mit einem **Platzhalter**, in den du einen anderen Typ einsetzt. So etwas heisst **Generic**.

In Angular triffst du ständig auf spitze Klammern: `signal<number>(0)`, `input<string>()`, `HttpClient.get<Benutzer[]>(...)`. Hier lernst du, sie zu lesen – und selbst zu schreiben.

## Das Problem

Angenommen, du willst eine Funktion, die das erste Element eines Arrays zurückgibt. Für Zahlen:

```ts
function erstesVonZahlen(liste: number[]): number | undefined {
  return liste[0];
}
console.log(erstesVonZahlen([4, 5]));
```

Für Strings bräuchtest du dieselbe Funktion nochmal mit `string`. Für Bücher nochmal. Das ist Unsinn – der Code ist jedes Mal derselbe.

## Die Lösung: ein Typ-Parameter

```ts
function erstes<T>(liste: T[]): T | undefined {
  return liste[0];
}

const zahl = erstes([4, 5, 6]);       // Typ: number | undefined
const wort = erstes(["a", "b"]);      // Typ: string | undefined
console.log(zahl, wort);
```

`<T>` hinter dem Funktionsnamen führt einen **Typ-Parameter** ein. `T` ist ein Platzhalter: «irgendein Typ, den ich noch nicht kenne». Die Funktion sagt damit: «Gib mir ein Array von `T`, und ich gebe dir ein `T` zurück.»

Beim Aufruf erkennt TypeScript selbst, was `T` ist: Übergibst du ein `number[]`, ist `T` gleich `number`. Der Rückgabetyp stimmt automatisch.

Der Name `T` (für «Type») ist Tradition. Du darfst auch `TElement` oder `Eintrag` schreiben.

## Generische Interfaces

Auch Interfaces können Platzhalter haben. Ein typisches Beispiel ist die Antwort eines Servers: Die Verpackung ist immer gleich, der Inhalt jedes Mal anders.

```ts
interface Antwort<T> {
  erfolgreich: boolean;
  daten: T;
}

const a: Antwort<number> = { erfolgreich: true, daten: 42 };
const b: Antwort<string[]> = { erfolgreich: true, daten: ["Mia", "Noah"] };

console.log(a.daten + 1, b.daten.length);
```

Bei Interfaces musst du den Typ in den spitzen Klammern immer selbst angeben.

## Den Typ ausdrücklich angeben

Manchmal kann TypeScript `T` nicht erraten – zum Beispiel bei einem leeren Array. Dann schreibst du ihn in spitzen Klammern dazu:

```ts
const namen = new Array<string>();
namen.push("Mia");
console.log(namen);
```

Genau das tust du später in Angular: `signal<string[]>([])` heisst «ein Signal, das ein Array von Strings enthält und leer startet».

> [!MERKE] Spitze Klammern lesen
> Lies `<...>` als «von» oder «mit»: `Array<string>` = Array von Strings, `Antwort<Buch>` = Antwort mit einem Buch, `Promise<number>` = Versprechen auf eine Zahl.

=== weitere-typen | Tupel, Record und nützliche Helfer | 15
Drei Werkzeuge, die dir in echtem Code regelmässig begegnen. Du musst sie nicht auswendig können – aber wiedererkennen.

## Tupel: Arrays mit fester Länge

Ein Tupel ist ein Array, bei dem **jede Position ihren eigenen Typ** hat:

```ts
const koordinate: [number, number] = [47.37, 8.54];
const eintrag: [string, number] = ["Mia", 15];

console.log(koordinate[0], eintrag[0].toUpperCase(), eintrag[1] + 1);
```

`[string, number]` heisst: genau zwei Elemente, zuerst ein Text, dann eine Zahl.

## Record: Nachschlagetabellen

Manchmal kennst du die Namen der Eigenschaften nicht im Voraus – etwa bei einer Tabelle «Wort → wie oft kommt es vor». Dafür gibt es `Record<Schlüsseltyp, Werttyp>`:

```ts
const punkte: Record<string, number> = {};

punkte["Mia"] = 12;
punkte["Noah"] = 9;
punkte["Mia"] += 3;

console.log(punkte); // { Mia: 15, Noah: 9 }
```

Mit eckigen Klammern greifst du über einen **berechneten** Namen zu: `punkte[name]`. Das ist die Schreibweise für Eigenschaften, deren Namen in einer Variable stecken.

Noch nützlicher wird `Record` mit einer festen Auswahl als Schlüssel. Dann prüft TypeScript, dass du **keinen Schlüssel vergisst**:

```ts
type Ampelfarbe = "rot" | "gelb" | "grün";

const bedeutung: Record<Ampelfarbe, string> = {
  rot: "anhalten",
  gelb: "bremsen",
  grün: "fahren",
};
```

## Helfer, die aus Typen neue Typen machen

TypeScript bringt Werkzeuge mit, die einen vorhandenen Typ abwandeln:

```ts
interface Benutzer {
  id: number;
  name: string;
  email: string;
}

type BenutzerEntwurf = Partial<Benutzer>;          // alle Eigenschaften optional
type BenutzerOhneId = Omit<Benutzer, "id">;         // alles ausser id
type NurName = Pick<Benutzer, "name">;              // nur name

const entwurf: BenutzerEntwurf = { name: "Mia" };
const neu: BenutzerOhneId = { name: "Mia", email: "mia@example.com" };
const kurz: NurName = { name: "Mia" };
console.log(entwurf, neu, kurz);
```

`Omit<Benutzer, "id">` ist zum Beispiel praktisch für ein Formular «Neuer Benutzer»: Dort gibt es alles ausser der `id`, denn die vergibt erst der Server.

Schreibe eine Funktion `zaehleBuchstaben`, die einen Text bekommt und ein `Record<string, number>` zurückgibt: zu jedem Zeichen, wie oft es im Text vorkommt.

Beispiel: `zaehleBuchstaben("hallo")` ergibt `{ h: 1, a: 1, l: 2, o: 1 }`.

Tipp: Über die Zeichen eines Strings kannst du mit `for (const zeichen of text)` gehen.
@starter
// Schreibe hier die Funktion zaehleBuchstaben

@solution
// Schreibe hier die Funktion zaehleBuchstaben
function zaehleBuchstaben(text: string): Record<string, number> {
  const anzahl: Record<string, number> = {};
  for (const zeichen of text) {
    anzahl[zeichen] = (anzahl[zeichen] ?? 0) + 1;
  }
  return anzahl;
}

console.log(zaehleBuchstaben("hallo"));

run Object.keys(zaehleBuchstaben("")).length === 0 :: Ein leerer Text ergibt ein leeres Objekt
run zaehleBuchstaben("aaa").a === 3 :: `"aaa"` ergibt `{ a: 3 }`

=== spread-destructuring | Auspacken und Kopieren: Destructuring und Spread | 20
Zwei Schreibweisen, die Code kürzer machen – und die du für Angular unbedingt brauchst. Besonders der zweite Teil dieser Lektion (Kopieren statt Verändern) ist die Grundlage dafür, wie Angular Änderungen bemerkt.

## Destructuring: Werte auspacken

Statt jede Eigenschaft einzeln aus einem Objekt zu holen …

```ts
const buch = { titel: "Momo", autor: "Michael Ende", seiten: 304 };

const titel1 = buch.titel;
const seiten1 = buch.seiten;
console.log(titel1, seiten1);
```

… kannst du mehrere auf einmal «auspacken»:

```ts
const buch = { titel: "Momo", autor: "Michael Ende", seiten: 304 };

const { titel, seiten } = buch;
console.log(titel, seiten); // "Momo" 304
```

Die geschweiften Klammern stehen hier **links** vom Gleichheitszeichen. Die Namen darin müssen den Eigenschaften entsprechen. Es entstehen zwei normale Variablen `titel` und `seiten`.

Bei Arrays geht dasselbe mit eckigen Klammern. Hier zählt die Position:

```ts
const koordinate = [47.37, 8.54];
const [breite, laenge] = koordinate;
console.log(breite, laenge);
```

Sehr beliebt ist Destructuring direkt in den Parametern einer Funktion:

```ts
interface Buch {
  titel: string;
  seiten: number;
}

function beschreibe({ titel, seiten }: Buch): string {
  return `${titel} (${seiten} Seiten)`;
}

console.log(beschreibe({ titel: "Momo", seiten: 304 }));
```

## Spread: Inhalte ausbreiten

Drei Punkte `...` vor einem Array oder Objekt «breiten» seinen Inhalt aus. Damit erstellst du **Kopien** – auf Wunsch mit Änderungen:

```ts
const zahlen = [1, 2, 3];
const mehrZahlen = [...zahlen, 4, 5];
console.log(mehrZahlen); // [ 1, 2, 3, 4, 5 ]
console.log(zahlen);     // [ 1, 2, 3 ] – unverändert

const buch = { titel: "Momo", seiten: 304 };
const neueAuflage = { ...buch, seiten: 320 };
console.log(neueAuflage); // { titel: 'Momo', seiten: 320 }
console.log(buch);        // { titel: 'Momo', seiten: 304 } – unverändert
```

Bei Objekten gilt: Was **weiter hinten** steht, gewinnt. `{ ...buch, seiten: 320 }` kopiert erst alles aus `buch` und überschreibt dann `seiten`.

## Warum kopieren statt verändern?

Bisher hast du Arrays mit `push` verändert und Objekte mit `objekt.eigenschaft = ...`. Das ist nicht falsch. Aber in Angular (und vielen anderen Frameworks) gilt eine wichtige Regel:

> [!MERKE] Daten nicht verändern, sondern ersetzen
> Angular bemerkt Änderungen daran, dass ein **neuer Wert** gesetzt wird. Wenn du nur den Inhalt eines bestehenden Arrays veränderst, bleibt es dasselbe Array – und Angular bekommt unter Umständen nichts mit. Deshalb erstellt man eine geänderte **Kopie** und setzt diese als neuen Wert.

Die drei häufigsten Fälle solltest du im Schlaf können:

```ts
interface Todo {
  id: number;
  titel: string;
  erledigt: boolean;
}

const todos: Todo[] = [
  { id: 1, titel: "Mathe", erledigt: false },
  { id: 2, titel: "Sport", erledigt: false },
];

// 1. Hinzufügen: neues Array mit einem Element mehr
const mitNeuem = [...todos, { id: 3, titel: "Musik", erledigt: false }];

// 2. Entfernen: filter liefert ein neues Array ohne das Element
const ohneZwei = todos.filter((todo) => todo.id !== 2);

// 3. Ändern: map liefert ein neues Array; nur das passende Element wird ersetzt
const einsErledigt = todos.map((todo) =>
  todo.id === 1 ? { ...todo, erledigt: true } : todo
);

console.log(mitNeuem.length, ohneZwei.length, einsErledigt[0].erledigt);
console.log(todos[0].erledigt); // false – das Original ist unverändert
```

Schau dir Fall 3 genau an: `map` geht alle Todos durch. Beim Todo mit der gesuchten `id` entsteht eine Kopie mit `erledigt: true`, alle anderen werden unverändert übernommen. Dieses Muster wirst du in der Abschluss-App exakt so verwenden.

--- code spread-kopieren | Kopieren statt verändern
Schreibe drei Funktionen, die jeweils ein **neues** Array zurückgeben und das übergebene Array **nicht verändern**:

- `hinzufuegen(todos, titel)` – hängt ein neues Todo mit diesem Titel an. Es bekommt `erledigt: false` und als `id` die Anzahl der bisherigen Todos plus 1.
- `entfernen(todos, id)` – liefert alle Todos ausser dem mit dieser `id`.
- `abhaken(todos, id)` – setzt beim Todo mit dieser `id` `erledigt` auf `true`. Alle anderen bleiben, wie sie sind.
@starter
interface Todo {
  id: number;
  titel: string;
  erledigt: boolean;
}

// Schreibe hier hinzufuegen, entfernen und abhaken

const start: Todo[] = [{ id: 1, titel: "Mathe", erledigt: false }];
const mehr = hinzufuegen(start, "Sport");
console.log(mehr);
console.log(abhaken(mehr, 1));
console.log(entfernen(mehr, 1));
@solution
interface Todo {
  id: number;
  titel: string;
  erledigt: boolean;
}

// Schreibe hier hinzufuegen, entfernen und abhaken
function hinzufuegen(todos: Todo[], titel: string): Todo[] {
  return [...todos, { id: todos.length + 1, titel, erledigt: false }];
}

function entfernen(todos: Todo[], id: number): Todo[] {
  return todos.filter((todo) => todo.id !== id);
}

function abhaken(todos: Todo[], id: number): Todo[] {
  return todos.map((todo) => (todo.id === id ? { ...todo, erledigt: true } : todo));
}

const start: Todo[] = [{ id: 1, titel: "Mathe", erledigt: false }];
const mehr = hinzufuegen(start, "Sport");
console.log(mehr);
console.log(abhaken(mehr, 1));
console.log(entfernen(mehr, 1));
@tests

run __a.length === 1 && __b !== __a :: `hinzufuegen` verändert das ursprüngliche Array nicht ?? `push` verändert das Original. Erstelle ein neues Array mit `[...todos, neuesTodo]`.

run __c.length === 1 && __c[0].id === 2 && __b.length === 2 :: `entfernen` liefert ein neues Array ohne das Todo – das Original bleibt

setup const __d = abhaken(__b, 1);
run __d.length === 2 && __d[0].erledigt === true && __d[1].erledigt === false :: `abhaken` setzt nur beim richtigen Todo `erledigt: true`
run __b[0].erledigt === false && __d[0] !== __b[0] :: `abhaken` verändert das ursprüngliche Todo nicht ?? `todo.erledigt = true` verändert das Original. Erstelle eine Kopie: `{ ...todo, erledigt: true }`.
run __d[1] === __b[1] :: Unveränderte Todos werden einfach übernommen (nicht kopiert)
@hints
- Hinzufügen: `return [...todos, { id: todos.length + 1, titel: titel, erledigt: false }];`
- Entfernen: `return todos.filter((todo) => todo.id !== id);`
- Abhaken: `return todos.map((todo) => todo.id === id ? { ...todo, erledigt: true } : todo);`
@after
Hinzufügen mit Spread, Entfernen mit `filter`, Ändern mit `map` und Spread: Das sind die drei Handgriffe, mit denen du in Angular jede Liste verwaltest. Übrigens: Statt `titel: titel` darf man kurz `titel` schreiben, wenn Eigenschaft und Variable gleich heissen.
