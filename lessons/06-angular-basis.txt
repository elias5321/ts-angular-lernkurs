=== angular-ueberblick | Was ist Angular? | 15
Du kannst jetzt TypeScript. Zeit für den Baukasten, mit dem daraus Web-Apps werden.

## Das Problem, das Angular löst

Mit reinem JavaScript musst du jede Änderung auf der Seite von Hand erledigen: Element suchen, Text setzen, Klasse ändern, Liste neu aufbauen. Bei einer kleinen Seite geht das. Bei einer App mit vielen Ansichten und Daten wird es schnell unübersichtlich und fehleranfällig.

Angular dreht das um. Du beschreibst zwei Dinge:

1. **Die Daten** – in TypeScript: «Es gibt einen Zähler, er steht auf 0.»
2. **Wie die Seite aussehen soll** – in HTML mit ein paar Zusätzen: «Zeige hier den Zähler an.»

Ändern sich die Daten, bringt Angular die Seite **automatisch** auf den neuesten Stand. Du fasst das HTML nie von Hand an.

## Alles ist eine Komponente

Eine Angular-App besteht aus **Komponenten**. Eine Komponente ist ein eigenständiger Baustein der Oberfläche: ein Knopf, eine Karte, eine Liste, eine ganze Seite. Komponenten werden ineinander verschachtelt wie Lego-Steine.

Stell dir eine Aufgaben-App vor:

- `App` – der äusserste Rahmen
- darin eine `Kopfzeile`
- darin eine `AufgabenListe`
- darin für jede Aufgabe eine `AufgabenKarte`

Jede Komponente besteht aus drei Teilen:

| Teil | Datei | Inhalt |
| --- | --- | --- |
| Klasse | `karte.ts` | Daten und Verhalten, in TypeScript |
| Template | `karte.html` | das Aussehen, in HTML |
| Styles | `karte.css` | die Gestaltung, in CSS |

## So sieht eine Komponente aus

```ts ng
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-zaehler',
  template: `
    <p>Zählerstand: {{ stand() }}</p>
    <button (click)="erhoehe()">Plus 1</button>
  `,
})
export class Zaehler {
  readonly stand = signal(0);

  erhoehe(): void {
    this.stand.update((wert) => wert + 1);
  }
}
```

Fast alles davon kannst du schon lesen:

- `import { ... } from '@angular/core'` – etwas aus dem Angular-Paket holen.
- `export class Zaehler { ... }` – eine Klasse mit einer Eigenschaft und einer Methode.
- `(wert) => wert + 1` – eine Pfeilfunktion.

Neu sind drei Dinge, die du in den nächsten Lektionen lernst:

- `@Component({...})` – ein **Decorator**. Dazu gleich mehr.
- `signal(0)` – ein **Signal**: ein Wert, bei dem Angular mitbekommt, wenn er sich ändert.
- `{{ stand() }}` und `(click)="..."` – die **Template-Syntax**, mit der HTML und Klasse verbunden werden.

## Decorators

Ein Decorator beginnt mit `@` und steht direkt vor einer Klasse. Er hängt der Klasse Zusatzinformationen an. `@Component({...})` sagt Angular: «Diese Klasse ist eine Komponente. Hier ist ihr HTML-Name und ihr Template.»

Ohne den Decorator wäre `Zaehler` eine gewöhnliche Klasse. Erst der Decorator macht daraus einen Baustein, den Angular auf der Seite anzeigen kann.

Angular läuft nicht hier im Browser-Editor – eine Angular-App wird aus vielen Dateien zusammengebaut, und dafür braucht es die Werkzeuge auf deinem Computer. Ab jetzt arbeitest du deshalb zweigleisig:

- **Hier im Kurs** schreibst du den Code der Komponenten. Geprüft werden die Typen und der Aufbau.

## Die Angular CLI installieren

Die **CLI** («Command Line Interface») ist das Kommandozeilen-Werkzeug von Angular. Der Befehl heisst `ng`. Damit erstellst du Projekte, startest sie und erzeugst neue Komponenten.

Öffne ein Terminal (in VS Code oder das Terminal-Programm deines Computers) und installiere die CLI:

```bash
npm install -g @angular/cli
```

Das `-g` steht für «global»: Der Befehl `ng` ist danach in jedem Ordner verfügbar. Prüfe es mit:

```bash
ng version
```

Es erscheint eine Übersicht mit der Versionsnummer.

> [!WARN] Wenn die Installation scheitert
> - **Mac/Linux, Meldung mit «EACCES» oder «permission denied»:** Dir fehlt die Berechtigung für globale Installationen. Du kannst die CLI dann einfach ohne Installation benutzen: Schreibe überall `npx @angular/cli` statt `ng`, beim Erstellen also `npx @angular/cli new erste-app`. Innerhalb eines Projekts funktioniert danach `npx ng serve`.
> - **Windows, «Die Ausführung von Skripts ist deaktiviert»:** Schau in der Lektion «Deinen Computer einrichten» nach – dort steht der Befehl, der das behebt.

## Ein Projekt erstellen

Wechsle im Terminal in den Ordner, in dem das Projekt liegen soll (zum Beispiel «Dokumente»), und führe aus:

```bash
ng new erste-app
```

Die CLI stellt ein paar Fragen. Mit den Pfeiltasten wählst du aus, mit [[Enter]] bestätigst du:

| Frage | Deine Antwort |
| --- | --- |
| Which stylesheet system would you like to use? | **CSS** |
| Do you want to enable Server-Side Rendering (SSR) …? | **No** (tippe `n`) |
| Fragen zu KI-Werkzeugen oder Ähnlichem | [[Enter]] für den Standard bzw. «None» |

Danach lädt die CLI alle nötigen Pakete herunter. Das dauert eine oder zwei Minuten.

## Das Projekt öffnen und starten

Öffne den neuen Ordner `erste-app` in VS Code (**Datei → Ordner öffnen**). Öffne dort ein Terminal und starte die App:

```bash
ng serve
```

Nach ein paar Sekunden erscheint eine Meldung mit einer Adresse. Öffne im Browser:

```text
http://localhost:4200
```

Du siehst die Startseite deiner ersten Angular-App.

`ng serve` startet einen **Entwicklungsserver**. Er läuft, solange das Terminal offen ist, und er beobachtet deine Dateien: Sobald du etwas speicherst, wird die App neu gebaut und der Browser lädt automatisch neu. Du beendest ihn mit [[Strg]] + [[C]].

> [!TIP] Zwei Terminals
> Lass `ng serve` in einem Terminal laufen und öffne für andere Befehle ein zweites (mit dem **+** im Terminal-Bereich). Wenn du `ng serve` beendest, ist die Seite im Browser nicht mehr erreichbar.

## Die erste Änderung

Öffne die Datei `src/app/app.html`. Sie enthält einen langen Platzhalter. Lösche **alles** und schreibe stattdessen:

```html
<h1>Hallo Angular!</h1>
```

Speichere. Der Browser zeigt sofort deine Überschrift.

## Fehler erscheinen an drei Stellen

Wenn in einem Angular-Projekt etwas nicht stimmt, siehst du das:

1. **in VS Code** als rote Linie – auch im HTML-Template, dank der Erweiterung «Angular Language Service»;
2. **im Terminal**, in dem `ng serve` läuft;
3. **im Browser** als Überlagerung über der Seite.

Bei Fehlern, die erst beim Benutzen der App auftreten, hilft die **Konsole des Browsers**: Drücke [[F12]] und wähle den Reiter «Konsole» (Console). Dort landen auch deine `console.log`-Ausgaben.

## Wie die App startet

Drei Dateien spielen zusammen. Schau sie dir in deinem Projekt an.

**1. `src/index.html`** enthält im `<body>` nur ein einziges, unbekanntes Element:

```html
<body>
  <app-root></app-root>
</body>
```

**2. `src/main.ts`** startet Angular und sagt, welche Komponente zuerst angezeigt wird:

```ts nocheck
import { bootstrapApplication } from '@angular/platform-browser';
import { appConfig } from './app/app.config';
import { App } from './app/app';

bootstrapApplication(App, appConfig).catch((err) => console.error(err));
```

**3. `src/app/app.ts`** ist diese erste Komponente – die **Wurzelkomponente**:

```ts nocheck
import { Component, signal } from '@angular/core';
import { RouterOutlet } from '@angular/router';

@Component({
  imports: [RouterOutlet],
  selector: 'app-root',
  styleUrl: './app.css',
  templateUrl: './app.html',
})
export class App {
  protected readonly title = signal('erste-app');
}
```

Der Zusammenhang: `selector: 'app-root'` legt fest, dass diese Komponente überall dort erscheint, wo im HTML `<app-root>` steht. Und genau das steht in `index.html`. Angular ersetzt also `<app-root>` durch das Template der Komponente `App`.

## Die Angaben im Decorator

| Angabe | Bedeutung |
| --- | --- |
| `selector` | der HTML-Name der Komponente |
| `templateUrl` | Pfad zur HTML-Datei mit dem Template |
| `styleUrl` | Pfad zur CSS-Datei |
| `imports` | andere Komponenten und Werkzeuge, die im Template benutzt werden |

Statt `templateUrl` kann man mit `template: '...'` das HTML auch direkt in die TypeScript-Datei schreiben. Das eignet sich für sehr kleine Komponenten. Die CLI erzeugt standardmässig getrennte Dateien, und so machen wir es im Kurs auch.

## Die Dateien im Ordner app

| Datei | Inhalt |
| --- | --- |
| `app.ts` | die Klasse der Wurzelkomponente |
| `app.html` | ihr Template |
| `app.css` | ihre Styles |
| `app.spec.ts` | automatische Tests (in diesem Kurs nicht behandelt) |
| `app.config.ts` | Grundeinstellungen der App |
| `app.routes.ts` | die Seiten der App (kommt beim Routing) |

In der generierten Klasse steht `protected readonly title = signal('erste-app');`. Du kannst jedes Wort lesen: eine Eigenschaft `title`, sichtbar für die Klasse und ihr Template (`protected`), die nie ersetzt wird (`readonly`), und die ein Signal mit dem Text `'erste-app'` enthält.

> [!NOTE] protected oder nicht?
> Angular empfiehlt `protected` für alles, was nur das eigene Template braucht. In den Übungen hier lassen wir das Wort oft weg, damit der Code kürzer bleibt – dann ist die Eigenschaft `public`. Beides funktioniert. `readonly` schreiben wir bei Signals immer: Das Signal selbst wird nie ausgetauscht, nur sein Inhalt ändert sich.

=== komponenten | Daten im Template anzeigen | 20
Die Klasse einer Komponente hält die Daten, das Template zeigt sie an. Die Verbindung zwischen beiden heisst **Interpolation** – und sie ist der erste Schritt zu einer lebendigen Seite.

## Signals: Werte, die Angular beobachtet

Daten, die im Template angezeigt werden und sich ändern können, legst du als **Signal** an:

```ts ng
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  templateUrl: './app.html',
})
export class App {
  readonly name = signal('Mia');
  readonly punkte = signal(120);
}
```

Ein Signal ist eine kleine Schachtel um einen Wert. `signal('Mia')` erzeugt ein Signal mit dem Startwert `'Mia'`. TypeScript erkennt den Typ von selbst: `name` ist ein `WritableSignal<string>` – ein Generic, wie du es kennst.

Um den Wert zu **lesen**, rufst du das Signal wie eine Funktion auf: `name()`. Die Klammern sind wichtig. `name` ist die Schachtel, `name()` ist ihr Inhalt.

## Interpolation: doppelte geschweifte Klammern

Im Template schreibst du zwischen `{{` und `}}` einen Ausdruck. Angular rechnet ihn aus und setzt das Ergebnis als Text ein:

```html
<h1>Hallo {{ name() }}!</h1>
<p>Du hast {{ punkte() }} Punkte.</p>
<p>Verdoppelt wären das {{ punkte() * 2 }}.</p>
<p>Dein Name hat {{ name().length }} Buchstaben.</p>
```

Zwischen den Klammern darf alles stehen, was einen Wert ergibt: Signale lesen, rechnen, Methoden aufrufen, die Kurzform `bedingung ? a : b`. Nicht erlaubt sind Anweisungen wie `if`, `for` oder Zuweisungen mit `=`.

Im Template schreibst du **kein** `this.`. Alles, was du dort verwendest, wird automatisch in der Klasse der Komponente gesucht.

## Warum Signals?

Wenn sich der Wert eines Signals ändert, weiss Angular genau, welche Stellen im Template davon abhängen – und aktualisiert **nur diese**. Du musst nichts weiter tun. Wie man Werte ändert, lernst du in der nächsten Lektion.

> [!WARN] Der häufigste Anfängerfehler
> `{{ name }}` ohne Klammern zeigt nicht den Namen an, sondern die Schachtel selbst – auf der Seite erscheint dann etwas wie `[Signal: Mia]`. Signale liest man immer mit Klammern: `{{ name() }}`.

## Feste Werte

Werte, die sich nie ändern, brauchen kein Signal. Eine gewöhnliche `readonly`-Eigenschaft reicht:

```ts ng
import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `<footer>{{ copyright }} · Version {{ version }}</footer>`,
})
export class App {
  readonly copyright = '© Meine Schule';
  readonly version = 3;
}
```

Als Faustregel: Kann sich etwas ändern, während die App läuft → Signal. Sonst → normale Eigenschaft.

=== signals | Signals ändern und auf Klicks reagieren | 25
Eine Seite, die nur anzeigt, ist langweilig. Jetzt reagiert deine Komponente auf den Benutzer – und du lernst, wie sich Signale ändern.

## Auf Ereignisse reagieren

Im Template verbindest du ein Ereignis mit einer Methode der Klasse. Das Ereignis steht in **runden** Klammern:

```html
<button (click)="erhoehe()">Plus 1</button>
```

Lies es so: «Wenn auf diesen Knopf geklickt wird, rufe `erhoehe()` auf.» Das nennt man **Event Binding**. Neben `click` gibt es viele weitere Ereignisse: `input` (Eingabe in ein Feld), `keydown` (Taste gedrückt), `submit` (Formular abgeschickt), `mouseenter` und so weiter.

## Signale ändern

Ein Signal hat zwei Methoden zum Ändern:

- `set(neuerWert)` – ersetzt den Wert.
- `update(funktion)` – berechnet den neuen Wert **aus dem alten**. Du übergibst eine Pfeilfunktion, die den alten Wert bekommt und den neuen zurückgibt.

```ts ng
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-zaehler',
  template: `
    <p>Stand: {{ stand() }}</p>
    <button (click)="erhoehe()">Plus 1</button>
    <button (click)="zuruecksetzen()">Zurücksetzen</button>
  `,
})
export class Zaehler {
  readonly stand = signal(0);

  erhoehe(): void {
    this.stand.update((wert) => wert + 1);
  }

  zuruecksetzen(): void {
    this.stand.set(0);
  }
}
```

In der Klasse brauchst du wieder `this.` – nur im Template fällt es weg.

Sobald `set` oder `update` aufgerufen wird, aktualisiert Angular automatisch alle Stellen im Template, die `stand()` anzeigen. Das ist der ganze Zauber.

> [!MERKE] Lesen, setzen, aktualisieren
> - Lesen: `stand()`
> - Ersetzen: `stand.set(5)`
> - Aus dem alten Wert berechnen: `stand.update((alt) => alt + 1)`

## Signale mit Arrays und Objekten

Hier zahlt sich aus, was du über Kopieren statt Verändern gelernt hast. Ein Signal bemerkt eine Änderung nur, wenn es einen **neuen Wert** bekommt:

```ts ng
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-liste',
  template: `<p>{{ namen().length }} Namen</p>`,
})
export class Liste {
  readonly namen = signal<string[]>([]);

  hinzufuegen(name: string): void {
    this.namen.update((alt) => [...alt, name]); // neues Array
  }
}
```

`signal<string[]>([])` gibt den Typ in spitzen Klammern an, weil TypeScript aus einem leeren Array nicht erraten kann, was hinein soll.

Falsch wäre `this.namen().push(name)`: Das verändert das bestehende Array, ohne dass das Signal etwas davon erfährt. Die Seite bliebe unverändert.

## Kleine Aktionen direkt im Template

Für ganz einfache Fälle darfst du die Änderung direkt ins Template schreiben:

```html
<button (click)="stand.set(0)">Zurücksetzen</button>
```

=== computed | Berechnete Werte: computed | 15
Viele Werte in einer App sind keine eigenen Daten, sondern ergeben sich aus anderen: der Gesamtpreis aus Preis und Menge, die Anzahl offener Aufgaben aus der Aufgabenliste. Solche Werte speicherst du nicht separat – du lässt sie **berechnen**.

## computed

```ts ng
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'app-warenkorb',
  template: `
    <p>{{ menge() }} × {{ preis() }} Franken = {{ gesamt() }} Franken</p>
    <button (click)="mehr()">Eins mehr</button>
  `,
})
export class Warenkorb {
  readonly preis = signal(4.5);
  readonly menge = signal(2);

  readonly gesamt = computed(() => this.preis() * this.menge());

  mehr(): void {
    this.menge.update((m) => m + 1);
  }
}
```

`computed` bekommt eine Pfeilfunktion, die den Wert ausrechnet. Das Ergebnis ist wieder ein Signal – du liest es genauso mit `gesamt()`.

Das Besondere: Angular merkt sich, welche Signale in der Funktion gelesen wurden (hier `preis` und `menge`). Ändert sich eines davon, wird `gesamt` automatisch neu berechnet. Du musst nie daran denken, es selbst zu aktualisieren.

## Warum nicht einfach ein zweites Signal?

Du könntest `gesamt` auch als normales Signal anlegen und in `mehr()` von Hand nachführen. Das geht so lange gut, bis du es an einer Stelle vergisst – dann zeigt die Seite einen falschen Preis. Mit `computed` kann das nicht passieren: Der Wert **folgt** immer aus seinen Quellen.

> [!MERKE] Eine Quelle der Wahrheit
> Speichere jede Information nur einmal. Alles, was sich daraus berechnen lässt, wird mit `computed` abgeleitet.

## Eigenschaften von computed

- **Nur lesbar:** Ein `computed` hat kein `set` und kein `update`. Der Typ ist `Signal<...>`, nicht `WritableSignal<...>`.
- **Sparsam:** Es rechnet nur neu, wenn sich eine seiner Quellen wirklich geändert hat – und nur, wenn jemand den Wert braucht.
- **Verkettbar:** Ein `computed` darf andere `computed` lesen.

=== property-binding | Eigenschaften binden | 20
Mit `{{ }}` setzt du **Text** ein. Oft willst du aber eine **Eigenschaft** eines Elements steuern: Ein Knopf soll deaktiviert sein, ein Bild soll eine bestimmte Datei zeigen, ein Element soll eine CSS-Klasse bekommen. Dafür gibt es **Property Binding**.

## Eckige Klammern

```html
<button [disabled]="stand() >= 10">Plus 1</button>
<img [src]="bildAdresse()" [alt]="bildBeschreibung()" />
<input [value]="name()" />
```

Steht ein Attribut in **eckigen** Klammern, ist der Wert in den Anführungszeichen kein Text, sondern ein **Ausdruck**, der in der Klasse ausgewertet wird. `[disabled]="stand() >= 10"` heisst: «Der Knopf ist deaktiviert, wenn der Stand mindestens 10 ist.»

Ohne eckige Klammern wäre es gewöhnliches HTML mit festem Text:

| Schreibweise | Bedeutung |
| --- | --- |
| `title="hilfe"` | das Wort «hilfe», fest |
| `[title]="hilfe()"` | der aktuelle Wert des Signals `hilfe` |

## Die drei Arten von Klammern

Damit hast du alle drei Verbindungen zwischen Template und Klasse beisammen:

| Schreibweise | Name | Richtung |
| --- | --- | --- |
| `{{ wert() }}` | Interpolation | Klasse → Text im Template |
| `[eigenschaft]="wert()"` | Property Binding | Klasse → Eigenschaft eines Elements |
| `(ereignis)="methode()"` | Event Binding | Template → Klasse |

Eselsbrücke: Eckige Klammern bringen Daten **hinein**, runde Klammern melden Ereignisse **heraus**.

## CSS-Klassen ein- und ausschalten

Sehr häufig soll ein Element je nach Zustand anders aussehen. Mit `[class.name]` schaltest du eine einzelne CSS-Klasse:

```html
<li [class.erledigt]="aufgabe.erledigt">{{ aufgabe.titel }}</li>
<p [class.warnung]="guthaben() < 10">Guthaben: {{ guthaben() }}</p>
```

Ist der Ausdruck `true`, bekommt das Element die Klasse, sonst nicht. Die Klasse selbst definierst du in der CSS-Datei der Komponente:

```css
.erledigt {
  text-decoration: line-through;
  color: gray;
}
```

## Einzelne Style-Werte

Für einzelne CSS-Eigenschaften gibt es `[style.eigenschaft]`. Praktisch für Werte, die berechnet werden:

```html
<div class="balken" [style.width.%]="fortschritt()"></div>
<p [style.color]="punkte() < 0 ? 'red' : 'green'">{{ punkte() }}</p>
```

`[style.width.%]="fortschritt()"` setzt die Breite in Prozent. Die Einheit hängst du mit einem Punkt an (`.px`, `.%`, `.rem`).

=== kontrollfluss-if | Etwas nur manchmal anzeigen: @if | 15
Nicht alles soll immer sichtbar sein. Eine Fehlermeldung erscheint nur bei einem Fehler, ein Lade-Hinweis nur während des Ladens. Im Template entscheidest du das mit `@if`.

## @if

```html
@if (punkte() >= 100) {
  <p>Gewonnen!</p>
}
```

Der Aufbau ist derselbe wie beim `if` in TypeScript: Bedingung in runden Klammern, Inhalt in geschweiften. Nur steht ein `@` davor, und in den geschweiften Klammern steht HTML.

Ist die Bedingung falsch, **existiert** der Inhalt auf der Seite gar nicht. Er ist nicht bloss versteckt.

## @else und @else if

```html
@if (note() >= 5.5) {
  <p>Hervorragend!</p>
} @else if (note() >= 4) {
  <p>Bestanden.</p>
} @else {
  <p>Leider nicht bestanden.</p>
}
```

## Typische Einsätze

**Leere Zustände:**

```html
@if (aufgaben().length === 0) {
  <p>Noch keine Aufgaben. Leg los!</p>
}
```

**Angemeldet oder nicht:**

```html
@if (angemeldet()) {
  <p>Willkommen zurück, {{ name() }}!</p>
  <button (click)="abmelden()">Abmelden</button>
} @else {
  <button (click)="anmelden()">Anmelden</button>
}
```

**Werte, die fehlen können.** Hier hilft Angular genau wie TypeScript mit Narrowing. Mit `; as` gibst du dem geprüften Wert einen Namen, unter dem er im Block sicher vorhanden ist:

```html
@if (ausgewaehlt(); as buch) {
  <h2>{{ buch.titel }}</h2>
  <p>{{ buch.seiten }} Seiten</p>
} @else {
  <p>Kein Buch ausgewählt.</p>
}
```

Hat `ausgewaehlt` den Typ `Signal<Buch | undefined>`, dann ist `buch` innerhalb des Blocks ein `Buch` – ohne `undefined`.

> In älteren Projekten und Anleitungen siehst du `<p *ngIf="bedingung">`. Das tut dasselbe, ist aber die alte Schreibweise. In neuem Code verwendest du `@if`.

=== kontrollfluss-for | Listen anzeigen: @for | 20
Fast jede App zeigt Listen: Aufgaben, Nachrichten, Produkte. Mit `@for` erzeugst du für jedes Element eines Arrays ein Stück HTML.

## @for

```html
<ul>
  @for (name of namen(); track name) {
    <li>{{ name }}</li>
  }
</ul>
```

Das ist die `for...of`-Schleife aus TypeScript, in HTML-Form. Für jedes Element in `namen()` entsteht ein `<li>`. Innerhalb der geschweiften Klammern steht das aktuelle Element in der Variable `name`.

## track ist Pflicht

Hinter dem Strichpunkt steht `track`. Damit sagst du Angular, **woran es ein Element wiedererkennt**. Ändert sich die Liste, muss Angular wissen, welche Einträge geblieben, dazugekommen oder verschwunden sind – nur so kann es die Seite gezielt aktualisieren, statt alles neu zu bauen.

- Haben die Elemente eine eindeutige Kennung, nimm die: `track aufgabe.id`.
- Bei einfachen, eindeutigen Werten (wie Namen ohne Doppelte) das Element selbst: `track name`.
- Nur wenn es gar nichts Eindeutiges gibt, die Position: `track $index`.

Deshalb haben Datenobjekte in Apps fast immer eine `id`.

## Listen von Objekten

```ts ng
import { Component, signal } from '@angular/core';

interface Aufgabe {
  id: number;
  titel: string;
  erledigt: boolean;
}

@Component({
  selector: 'app-aufgaben',
  templateUrl: './aufgaben.html',
})
export class Aufgaben {
  readonly aufgaben = signal<Aufgabe[]>([
    { id: 1, titel: 'Mathe', erledigt: true },
    { id: 2, titel: 'Deutsch', erledigt: false },
  ]);
}
```

```html
<ul>
  @for (aufgabe of aufgaben(); track aufgabe.id) {
    <li [class.erledigt]="aufgabe.erledigt">{{ aufgabe.titel }}</li>
  }
</ul>
```

`aufgabe` ist hier ein normales Objekt, kein Signal. Deshalb `aufgabe.titel` ohne Klammern – nur das Signal `aufgaben()` braucht sie.

## Leere Listen: @empty

Direkt nach dem `@for`-Block kannst du mit `@empty` festlegen, was erscheint, wenn das Array leer ist:

```html
<ul>
  @for (aufgabe of aufgaben(); track aufgabe.id) {
    <li>{{ aufgabe.titel }}</li>
  } @empty {
    <li>Keine Aufgaben vorhanden.</li>
  }
</ul>
```

## Die Position kennen

Innerhalb von `@for` stellt Angular Hilfsvariablen bereit:

| Variable | Bedeutung |
| --- | --- |
| `$index` | Position des Elements, ab 0 |
| `$first` | `true` beim ersten Element |
| `$last` | `true` beim letzten Element |
| `$count` | Anzahl Elemente insgesamt |

```html
@for (name of namen(); track name) {
  <p>{{ $index + 1 }}. {{ name }}</p>
}
```

## Aus der Liste heraus etwas auslösen

In der Schleife kannst du das aktuelle Element an eine Methode übergeben:

```html
@for (aufgabe of aufgaben(); track aufgabe.id) {
  <li>
    {{ aufgabe.titel }}
    <button (click)="entferne(aufgabe.id)">Löschen</button>
  </li>
}
```

So weiss die Methode, welcher Eintrag gemeint ist.

> [!NOTE] Älterer Code: *ngFor
> Die alte Schreibweise lautet `<li *ngFor="let name of namen">`. In neuem Code verwendest du `@for`.

=== eingaben | Eingaben des Benutzers lesen | 20
Bisher konnte der Benutzer nur klicken. Jetzt liest du, was er in ein Textfeld tippt.

## Eine Template-Variable

Mit einem `#` gibst du einem Element im Template einen Namen. Über diesen Namen kannst du an anderer Stelle im selben Template auf das Element zugreifen:

```html
<input #feld type="text" placeholder="Dein Name" />
<button (click)="begruesse(feld.value)">Hallo sagen</button>
```

`#feld` macht das Eingabefeld unter dem Namen `feld` verfügbar. `feld.value` ist der Text, der gerade darin steht. Beim Klick wird er an die Methode `begruesse` übergeben.

## Mit der Enter-Taste abschicken

Niemand will für jede Eingabe zur Maus greifen. Mit `(keydown.enter)` reagierst du gezielt auf die Enter-Taste:

```html
<input #feld type="text" (keydown.enter)="hinzufuegen(feld.value); feld.value = ''" />
```

Hier stehen zwei Anweisungen, getrennt durch einen Strichpunkt: zuerst die Methode aufrufen, dann das Feld leeren.

## Bei jedem Tastendruck mitlesen

Das Ereignis `input` wird bei jeder Änderung im Feld ausgelöst. So hältst du ein Signal ständig auf dem Stand des Feldes:

```ts ng
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'app-suche',
  template: `
    <input #feld type="text" [value]="suchtext()" (input)="suchtext.set(feld.value)" />
    <p>Du suchst nach: {{ suchtext() }} ({{ laenge() }} Zeichen)</p>
  `,
})
export class Suche {
  readonly suchtext = signal('');
  readonly laenge = computed(() => this.suchtext().length);
}
```

Zwei Bindungen arbeiten zusammen:

- `[value]="suchtext()"` – das Feld zeigt den Wert des Signals.
- `(input)="suchtext.set(feld.value)"` – jede Eingabe schreibt zurück ins Signal.

Damit ist das Signal die einzige Quelle der Wahrheit, und alles, was davon abhängt (`laenge`, eine gefilterte Liste …), aktualisiert sich bei jedem Tastendruck.

## Eingaben prüfen

Benutzer tippen Leerzeichen, schicken leere Felder ab und klicken doppelt. Eine robuste Methode räumt zuerst auf und bricht ab, wenn nichts Brauchbares da ist:

```ts ng
import { Component, signal } from '@angular/core';

@Component({ selector: 'app-namen', template: '' })
export class Namen {
  readonly namen = signal<string[]>([]);

  hinzufuegen(eingabe: string): void {
    const name = eingabe.trim();
    if (name === '') {
      return;
    }
    this.namen.update((alt) => [...alt, name]);
  }
}
```

Ein `return` ohne Wert beendet eine `void`-Methode vorzeitig.

> [!NOTE] Für grössere Formulare
> Diese Technik reicht für einzelne Felder. Für richtige Formulare mit mehreren Feldern und Prüfregeln hat Angular ein eigenes Werkzeug – das lernst du in der Lektion «Formulare».
