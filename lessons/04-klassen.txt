=== klassen | Klassen | 20
Bisher hast du Daten (Objekte) und Verhalten (Funktionen) getrennt geschrieben. Eine **Klasse** fasst beides zusammen: Sie ist ein Bauplan für Objekte, die Daten **und** dazugehörige Funktionen haben.

Für Angular ist das zentral: Jede Komponente, also jeder Baustein deiner App, ist eine Klasse.

## Eine Klasse schreiben

```ts
class Zaehler {
  wert: number = 0;

  erhoehe(): void {
    this.wert++;
  }
}

const klicks = new Zaehler();
klicks.erhoehe();
klicks.erhoehe();
console.log(klicks.wert); // 2
```

Was hier passiert:

- `class Zaehler { ... }` definiert den Bauplan. Klassennamen beginnen gross.
- `wert: number = 0;` ist eine **Eigenschaft** (englisch «property») mit Typ und Startwert. Davor steht kein `let` oder `const`.
- `erhoehe(): void { ... }` ist eine **Methode**: eine Funktion, die zur Klasse gehört. Davor steht kein `function`.
- `new Zaehler()` baut nach dem Bauplan ein Objekt. Man nennt es eine **Instanz**.

## this

Innerhalb einer Klasse greifst du mit `this.` auf die eigenen Eigenschaften und Methoden zu. `this` bedeutet «dieses Objekt hier».

Das `this.` darf nicht fehlen. Nur `wert++` zu schreiben, ist ein Fehler – TypeScript sucht dann nach einer gewöhnlichen Variable namens `wert` und findet keine.

Jede Instanz hat ihre eigenen Werte:

```ts
class Zaehler {
  wert: number = 0;

  erhoehe(): void {
    this.wert++;
  }
}

const a = new Zaehler();
const b = new Zaehler();
a.erhoehe();
console.log(a.wert, b.wert); // 1 0
```

## Der constructor

Oft braucht ein Objekt beim Erstellen Startwerte. Dafür gibt es eine besondere Methode namens `constructor`. Sie läuft automatisch bei `new`:

```ts
class Spieler {
  name: string;
  punkte: number = 0;

  constructor(name: string) {
    this.name = name;
  }

  gewinnePunkte(anzahl: number): void {
    this.punkte += anzahl;
  }

  beschreibung(): string {
    return `${this.name}: ${this.punkte} Punkte`;
  }
}

const mia = new Spieler("Mia");
mia.gewinnePunkte(50);
console.log(mia.beschreibung()); // Mia: 50 Punkte
```

Die Zeile `this.name = name;` sieht seltsam aus, ist aber logisch: Links steht die Eigenschaft des Objekts (`this.name`), rechts der Parameter des Constructors (`name`).

TypeScript prüft, dass jede Eigenschaft einen Wert bekommt – entweder direkt bei der Deklaration (`punkte: number = 0`) oder im Constructor (`this.name = name`). Vergisst du das, erscheint die Meldung *«Property has no initializer»*.

## Eine Klasse ist auch ein Typ

Der Klassenname lässt sich wie ein Interface als Typ verwenden:

```ts
class Spieler {
  name: string;

  constructor(name: string) {
    this.name = name;
  }
}

function begruesse(spieler: Spieler): string {
  return `Willkommen, ${spieler.name}!`;
}

const team: Spieler[] = [new Spieler("Mia"), new Spieler("Noah")];
console.log(begruesse(team[0]));
```

## Interface oder Klasse?

- **Interface:** nur die Form von Daten, ohne Verhalten. Verschwindet beim Übersetzen. Ideal für Daten wie `Buch` oder `Todo`.
- **Klasse:** Daten **mit** Methoden. Existiert auch im laufenden Programm. In Angular sind Komponenten und Services Klassen.

=== sichtbarkeit | Sichtbarkeit: private, protected und readonly | 15
Nicht alles in einer Klasse soll von aussen erreichbar sein. Ein Bankkonto soll seinen Kontostand nicht einfach überschreiben lassen – Änderungen sollen nur über `einzahlen` und `abheben` möglich sein. Dafür gibt es **Zugriffsmodifizierer**.

## public, private, protected

| Wort | Wer darf zugreifen? |
| --- | --- |
| `public` | alle (das ist der Standard, wenn nichts dasteht) |
| `private` | nur die Klasse selbst |
| `protected` | die Klasse selbst und Klassen, die von ihr erben (nächste Lektion) |

```ts
class Konto {
  private stand: number = 0;

  einzahlen(betrag: number): void {
    if (betrag > 0) {
      this.stand += betrag;
    }
  }

  kontostand(): number {
    return this.stand;
  }
}

const konto = new Konto();
konto.einzahlen(100);
console.log(konto.kontostand()); // 100
```

Ein direkter Zugriff von aussen wird abgelehnt:

```ts error
class Konto {
  private stand: number = 0;
}

const konto = new Konto();
konto.stand = 1000000;
```

So kann niemand den Kontostand an den Regeln vorbei verändern. Die Klasse behält die Kontrolle über ihre Daten. Dieses Prinzip heisst **Kapselung**.

## readonly

`readonly` kennst du von Interfaces. In Klassen bedeutet es: Die Eigenschaft bekommt ihren Wert bei der Deklaration oder im Constructor – und danach nie wieder einen anderen.

```ts
class Konto {
  readonly inhaber: string;
  private stand: number = 0;

  constructor(inhaber: string) {
    this.inhaber = inhaber;
  }

  kontostand(): number {
    return this.stand;
  }
}

const konto = new Konto("Mia");
console.log(konto.inhaber, konto.kontostand());
```

## Getter: Methoden, die wie Eigenschaften aussehen

Mit `get` schreibst du eine Methode, die man **ohne Klammern** liest. Das eignet sich für berechnete Werte:

```ts
class Rechteck {
  breite: number;
  hoehe: number;

  constructor(breite: number, hoehe: number) {
    this.breite = breite;
    this.hoehe = hoehe;
  }

  get flaeche(): number {
    return this.breite * this.hoehe;
  }
}

const r = new Rechteck(4, 5);
console.log(r.flaeche); // 20 – ohne Klammern
```

## Die Kurzschreibweise im Constructor

In vielen Projekten (und in älterem Angular-Code) siehst du diese Abkürzung:

```ts nocheck
class Konto {
  constructor(readonly inhaber: string, private stand: number = 0) {}
}
```

Steht im Constructor vor einem Parameter `public`, `private`, `protected` oder `readonly`, erzeugt TypeScript automatisch eine gleichnamige Eigenschaft und weist sie zu. Das spart drei Zeilen pro Eigenschaft.

> [!NOTE] Hinweis für dein Projekt ts-lernen
> Diese Kurzschreibweise ist reines TypeScript ohne Entsprechung in JavaScript. Wenn du eine solche Datei direkt mit `node datei.ts` startest, bekommst du eine Fehlermeldung, weil Node.js hier nicht einfach die Typen wegstreichen kann. Starte die Datei dann mit `node --experimental-transform-types datei.ts` – oder schreib die Eigenschaften aus, wie du es oben gelernt hast.

## So sieht es in Angular aus

In Angular-Komponenten wirst du `protected` und `readonly` oft zusammen sehen:

```ts nocheck
export class App {
  protected readonly titel = signal('Meine App');
}
```

Du kannst das jetzt lesen: eine Eigenschaft `titel`, die nur die Klasse selbst (und ihr Template) benutzen darf und die nie durch etwas anderes ersetzt wird.

--- code klasse-konto | Ein sicheres Konto
Schreibe eine Klasse `Konto`:

- `inhaber` – ein Text, **schreibgeschützt**, wird im Constructor übergeben
- `stand` – eine Zahl, **privat**, Startwert `0`
- `einzahlen(betrag)` – erhöht den Stand, aber nur wenn der Betrag grösser als 0 ist
- `abheben(betrag)` – verringert den Stand, aber nur wenn genug Geld da ist. Gibt `true` zurück, wenn es geklappt hat, sonst `false`.
- `kontostand()` – gibt den aktuellen Stand zurück
@starter

konto.einzahlen(100);
console.log(konto.abheben(30), konto.kontostand());
console.log(konto.abheben(500), konto.kontostand());
@solution
// Schreibe hier die Klasse Konto
class Konto {
  readonly inhaber: string;
  private stand: number = 0;

  constructor(inhaber: string) {
    this.inhaber = inhaber;
  }

  einzahlen(betrag: number): void {
    if (betrag > 0) {
      this.stand += betrag;
    }
  }

  abheben(betrag: number): boolean {
    if (betrag > this.stand) {
      return false;
    }
    this.stand -= betrag;
    return true;
  }

  kontostand(): number {
    return this.stand;
  }
}

const konto = new Konto("Mia");
konto.einzahlen(100);
console.log(konto.abheben(30), konto.kontostand());
console.log(konto.abheben(500), konto.kontostand());

@after

=== vererbung | Vererbung und implements | 15
Manchmal sind Klassen miteinander verwandt: Ein Auto und ein Velo sind beides Fahrzeuge. Gemeinsames schreibt man dann nur einmal – in einer Elternklasse – und die anderen Klassen **erben** davon.

In Angular schreibst du selten eigene Vererbung. Du solltest das Konzept aber kennen, weil du die Wörter `extends`, `super` und `implements` in fremdem Code antreffen wirst.

## extends

```ts
class Tier {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  vorstellen(): string {
    return `Ich bin ${this.name}.`;
  }
}

class Hund extends Tier {
  bellen(): string {
    return "Wuff!";
  }
}

const rex = new Hund("Rex");
console.log(rex.vorstellen()); // von Tier geerbt
console.log(rex.bellen());     // eigene Methode
```

`Hund extends Tier` bedeutet: Ein Hund kann alles, was ein Tier kann – und zusätzlich bellen.

## Methoden überschreiben

Eine Unterklasse kann eine geerbte Methode durch eine eigene Version ersetzen. Das kennzeichnest du mit `override`. Mit `super.` rufst du die Version der Elternklasse auf:

```ts
class Tier {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  vorstellen(): string {
    return `Ich bin ${this.name}.`;
  }
}

class Katze extends Tier {
  override vorstellen(): string {
    return `${super.vorstellen()} Miau!`;
  }
}

console.log(new Katze("Luna").vorstellen()); // Ich bin Luna. Miau!
```

## Eigener constructor in der Unterklasse

Braucht die Unterklasse zusätzliche Startwerte, schreibt sie einen eigenen Constructor. Darin **muss** als Erstes `super(...)` stehen – das ruft den Constructor der Elternklasse auf:

```ts
class Tier {
  name: string;

  constructor(name: string) {
    this.name = name;
  }
}

class Vogel extends Tier {
  spannweite: number;

  constructor(name: string, spannweite: number) {
    super(name);
    this.spannweite = spannweite;
  }
}

const adler = new Vogel("Adler", 2.2);
console.log(adler.name, adler.spannweite);
```

## implements: ein Versprechen abgeben

Mit `implements` verspricht eine Klasse, die Form eines Interfaces zu erfüllen. TypeScript prüft, ob sie das Versprechen hält:

```ts
interface Druckbar {
  alsText(): string;
}

class Rechnung implements Druckbar {
  betrag: number;

  constructor(betrag: number) {
    this.betrag = betrag;
  }

  alsText(): string {
    return `Rechnung über ${this.betrag} Franken`;
  }
}

console.log(new Rechnung(50).alsText());
```

Fehlt `alsText()`, gibt es einen Fehler. In Angular begegnet dir das zum Beispiel als `export class Profil implements OnInit` – die Klasse verspricht damit, eine Methode `ngOnInit()` zu haben.

=== module | Module: Code auf Dateien verteilen | 20
Bis jetzt stand alles in einer Datei. Eine echte App besteht aus Dutzenden oder Hunderten von Dateien. Damit eine Datei benutzen kann, was in einer anderen steht, gibt es **Module** – und die zwei Wörter `export` und `import`.

Jede Angular-Datei beginnt mit `import`-Zeilen. Nach dieser Lektion weisst du genau, was sie bedeuten.

## export: etwas freigeben

Jede Datei ist ein eigenes Modul. Was darin steht, ist zunächst **nur dort** sichtbar. Mit `export` gibst du etwas für andere Dateien frei:

```ts title=mathe.ts
export const PI = 3.14159;

export function quadrat(zahl: number): number {
  return zahl * zahl;
}

function hilfsfunktion(): void {
  // nicht exportiert: nur in dieser Datei sichtbar
}
```

Exportieren kannst du alles, was einen Namen hat: Funktionen, Variablen, Klassen, Interfaces und Typen.

## import: etwas hereinholen

```ts nocheck title=main.ts
import { PI, quadrat } from "./mathe";

console.log(quadrat(4));
console.log(PI);
```

So liest du die erste Zeile: «Hole `PI` und `quadrat` aus der Datei `mathe` im selben Ordner.»

- In den geschweiften Klammern stehen die Namen – genau so geschrieben wie beim `export`. (Das ist dieselbe Schreibweise wie beim Destructuring.)
- Hinter `from` steht der **Pfad** zur Datei, in Anführungszeichen.

## Pfade verstehen

| Pfad | Bedeutung |
| --- | --- |
| `"./mathe"` | Datei `mathe.ts` im **selben** Ordner |
| `"./daten/buch"` | Datei `buch.ts` im Unterordner `daten` |
| `"../mathe"` | Datei `mathe.ts` einen Ordner **weiter oben** |
| `"@angular/core"` | kein Pfad, sondern ein installiertes **Paket** aus `node_modules` |

Der Unterschied ist wichtig: Beginnt der Pfad mit `./` oder `../`, ist es eine eigene Datei. Beginnt er mit einem Namen, ist es ein Paket, das mit npm installiert wurde.

> [!WARN] Mit oder ohne Endung?
> In Angular-Projekten (und hier im Kurs) schreibt man den Pfad **ohne** `.ts`: `from "./mathe"`. In deinem Projekt `ts-lernen`, das du direkt mit Node.js startest, musst du die Endung **mitschreiben**: `from "./mathe.ts"`. Das liegt daran, dass Node.js die Datei selbst suchen muss, während bei Angular ein Werkzeug die Dateien vorher zusammenbaut.

## Typen importieren

Interfaces und Typen werden genauso exportiert und importiert:

```ts title=todo.ts

In Angular kommt das selten vor. Merke dir nur: mit Klammern = benannter Export (der Normalfall), ohne Klammern = Standard-Export.

=== promises | Warten können: Promises und async/await | 25
Manche Dinge brauchen Zeit: Daten von einem Server laden, eine Datei lesen, auf eine Eingabe warten. Würde das Programm dabei einfach stehen bleiben, wäre die ganze Webseite eingefroren. Deshalb läuft so etwas **asynchron**: Das Programm stösst die Aufgabe an, macht weiter – und kümmert sich um das Ergebnis, sobald es da ist.

## Erst später: setTimeout

Die einfachste asynchrone Funktion ist `setTimeout`. Sie ruft eine Funktion nach einer Wartezeit (in Millisekunden) auf:

```ts
console.log("1. Start");

setTimeout(() => {
  console.log("3. Eine halbe Sekunde später");
}, 500);

console.log("2. Ende des Programms");
```

Achte auf die Reihenfolge der Ausgabe: 1, 2, 3. Das Programm wartet **nicht** auf den Timer. Es merkt sich nur «in 500 ms diese Funktion aufrufen» und läuft sofort weiter.

## Promise: ein Versprechen auf einen Wert

Eine Funktion, die etwas Langsames tut, kann ihr Ergebnis nicht sofort zurückgeben. Stattdessen gibt sie ein **Promise** zurück – ein Versprechen: «Den Wert habe ich noch nicht, aber du bekommst ihn.»

Der Typ dafür ist generisch: `Promise<string>` ist das Versprechen auf einen Text, `Promise<Benutzer>` das Versprechen auf einen Benutzer.

Für die Beispiele hier simulieren wir einen langsamen Server:

```ts
function ladeName(): Promise<string> {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Mia"), 300);
  });
}

const versprechen = ladeName();
console.log(versprechen); // Promise { <pending> } – noch kein Name!
```

Wie man selbst ein Promise baut (`new Promise(...)`), musst du selten wissen. In der Praxis **benutzt** du fast immer Promises, die dir jemand anderes liefert. Wichtig ist nur: `ladeName()` gibt nicht `"Mia"` zurück, sondern ein Versprechen darauf.

## await: auf das Ergebnis warten

Um an den Wert zu kommen, schreibst du `await` vor das Promise. Das bedeutet: «Warte hier, bis das Versprechen eingelöst ist, und gib mir dann den Wert.»

`await` darf nur in Funktionen stehen, die mit `async` markiert sind:

```ts
function ladeName(): Promise<string> {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Mia"), 300);
  });
}

async function begruesse(): Promise<void> {
  console.log("Lade ...");
  const name = await ladeName(); // wartet 300 ms
  console.log(`Hallo ${name}!`); // name ist ein ganz normaler string
}

begruesse();
```

Dank `await` liest sich der Code von oben nach unten wie normaler Code – obwohl zwischendurch gewartet wird. Und das Beste: Nur diese eine Funktion pausiert. Der Rest der App läuft weiter.

## async-Funktionen geben immer ein Promise zurück

Eine `async`-Funktion kann ja selbst nicht sofort fertig sein. Deshalb ist ihr Rückgabetyp immer ein `Promise`:

```ts
function ladePunkte(): Promise<number> {
  return new Promise((resolve) => {
    setTimeout(() => resolve(120), 200);
  });
}

async function doppeltePunkte(): Promise<number> {
  const punkte = await ladePunkte();
  return punkte * 2; // du gibst eine number zurück – TypeScript verpackt sie in ein Promise
}

async function start(): Promise<void> {
  const ergebnis = await doppeltePunkte();
  console.log(ergebnis); // 240
}

start();
```

Wer eine `async`-Funktion aufruft, muss also wieder `await` davorschreiben, um an den Wert zu kommen. Das zieht sich durch: «async steckt an».

> [!WARN] Der häufigste Fehler: await vergessen
> Ohne `await` bekommst du nicht den Wert, sondern das Promise. TypeScript hilft dir meistens: Wenn du mit einem `Promise<number>` rechnen willst, gibt es einen Typfehler. Siehst du in einer Meldung `Promise<...>`, wo du einen normalen Wert erwartest, fehlt fast sicher ein `await`.

## Mehreres gleichzeitig: Promise.all

Mit `await` nacheinander zu warten, dauert so lange wie alle Wartezeiten zusammen. Sind die Aufgaben unabhängig, startest du sie gleichzeitig und wartest mit `Promise.all` auf alle:

```ts
function ladeZahl(zahl: number): Promise<number> {
  return new Promise((resolve) => {
    setTimeout(() => resolve(zahl), 200);
  });
}

async function start(): Promise<void> {
  const ergebnisse = await Promise.all([ladeZahl(1), ladeZahl(2), ladeZahl(3)]);
  console.log(ergebnisse); // [ 1, 2, 3 ] – nach 200 ms, nicht nach 600
}

start();
```

## Die ältere Schreibweise: then

Vor `async`/`await` hat man das Ergebnis mit `.then(...)` abgeholt. Du wirst es in fremdem Code noch sehen:

```ts
function ladeName(): Promise<string> {
  return new Promise((resolve) => {
    setTimeout(() => resolve("Mia"), 300);
  });
}

ladeName().then((name) => {
  console.log(`Hallo ${name}!`);
});
```

Das tut dasselbe wie `const name = await ladeName();`. Für neuen Code nimmst du `async`/`await` – es ist leichter zu lesen.

=== fehlerbehandlung | Wenn etwas schiefgeht: try und catch | 20
Typfehler findet TypeScript, bevor das Programm läuft. Aber manches kann erst **während** des Laufs schiefgehen: Der Server antwortet nicht, eine Datei fehlt, eine Eingabe ist unbrauchbar. Solche Fehler heissen **Laufzeitfehler**.

## Fehler auslösen: throw

Mit `throw` meldest du selbst einen Fehler. Die Funktion wird sofort abgebrochen:

```ts
function teile(a: number, b: number): number {
  if (b === 0) {
    throw new Error("Durch null kann man nicht teilen.");
  }
  return a / b;
}

console.log(teile(10, 2)); // 5
```

`new Error("...")` erzeugt ein Fehlerobjekt mit einer Meldung. Wird ein solcher Fehler nirgends abgefangen, stürzt das Programm ab und die Meldung erscheint in der Konsole.

## Fehler abfangen: try / catch

```ts
function teile(a: number, b: number): number {
  if (b === 0) {
    throw new Error("Durch null kann man nicht teilen.");
  }
  return a / b;
}

try {
  console.log(teile(10, 0));
  console.log("Diese Zeile wird übersprungen.");
} catch (fehler) {
  console.log("Das hat nicht geklappt.");
}

console.log("Das Programm läuft weiter.");
```

Der Code im `try`-Block wird ausgeführt. Tritt irgendwo darin ein Fehler auf, springt das Programm sofort in den `catch`-Block. Danach geht es normal weiter – kein Absturz.

## Was ist fehler für ein Typ?

Die Variable im `catch` hat den Typ `unknown`. Das ist richtig so: In JavaScript kann man mit `throw` alles werfen, nicht nur Fehlerobjekte. Um an die Meldung zu kommen, prüfst du mit `instanceof`, ob es ein `Error` ist:

```ts
try {
  throw new Error("Server nicht erreichbar");
} catch (fehler) {
  if (fehler instanceof Error) {
    console.log(`Fehler: ${fehler.message}`);
  } else {
    console.log("Unbekannter Fehler");
  }
}
```

`instanceof` fragt «Wurde dieses Objekt mit dieser Klasse gebaut?» – und ist damit eine weitere Art von Narrowing.

## Fehler bei async/await

Ein Promise kann auch scheitern (man sagt: es wird «rejected»). Mit `await` wird daraus ein ganz normaler Fehler, den du mit `try`/`catch` abfängst:

```ts
function ladeDaten(): Promise<string> {
  return new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error("Zeitüberschreitung")), 200);
  });
}

async function start(): Promise<void> {
  try {
    const daten = await ladeDaten();
    console.log(daten);
  } catch (fehler) {
    console.log("Laden fehlgeschlagen.");
  }
}

start();
```

Das ist der grosse Vorteil von `async`/`await`: Fehler behandelst du genauso wie bei normalem Code.

> [!MERKE] Wann try/catch?
> Nicht um jede Zeile ein `try` bauen. Sinnvoll ist es dort, wo etwas **von aussen** kommt und schiefgehen kann – Netzwerk, Speicher, Benutzereingaben – und wo du sinnvoll **reagieren** kannst, zum Beispiel mit einer Meldung für den Benutzer.

Das Interface `Eintrag` ist gegeben. Schreibe die Klasse `Notenbuch`:

- `eintraege` – ein **privates** Array von `Eintrag`, zu Beginn leer
- `hinzufuegen(eintrag)` – fügt einen Eintrag hinzu. Liegt die Note nicht zwischen 1 und 6, wirft die Methode einen `Error` mit der Meldung `Ungültige Note`.
- `anzahl()` – gibt zurück, wie viele Einträge es gibt
- `faecher()` – gibt ein Array mit allen Fächern zurück, **jedes nur einmal**, in der Reihenfolge des ersten Auftretens
- `durchschnitt(fach)` – gibt den Notendurchschnitt für dieses Fach zurück, oder `null`, wenn es zu dem Fach keine Noten gibt
- `bestesFach()` – gibt das Fach mit dem höchsten Durchschnitt zurück, oder `null`, wenn das Notenbuch leer ist

@solution
interface Eintrag {
  fach: string;
  note: number;
  art: "pruefung" | "muendlich";
}

class Notenbuch {
  private eintraege: Eintrag[] = [];

  hinzufuegen(eintrag: Eintrag): void {
    if (eintrag.note < 1 || eintrag.note > 6) {
      throw new Error("Ungültige Note");
    }
    this.eintraege = [...this.eintraege, eintrag];
  }

  anzahl(): number {
    return this.eintraege.length;
  }

  faecher(): string[] {
    const ergebnis: string[] = [];
    for (const eintrag of this.eintraege) {
      if (!ergebnis.includes(eintrag.fach)) {
        ergebnis.push(eintrag.fach);
      }
    }
    return ergebnis;
  }

  durchschnitt(fach: string): number | null {
    const noten = this.eintraege.filter((e) => e.fach === fach).map((e) => e.note);
    if (noten.length === 0) {
      return null;
    }
    const summe = noten.reduce((zwischenstand, note) => zwischenstand + note, 0);
    return summe / noten.length;
  }

  bestesFach(): string | null {
    let bestes: string | null = null;
    let besterSchnitt = 0;
    for (const fach of this.faecher()) {
      const schnitt = this.durchschnitt(fach) ?? 0;
      if (schnitt > besterSchnitt) {
        besterSchnitt = schnitt;
        bestes = fach;
      }
    }
    return bestes;
  }
}

@hints
- Beginne mit `private eintraege: Eintrag[] = [];`, dann `hinzufuegen` und `anzahl`. Prüfe nach jeder Methode.
- `faecher()`: Starte mit einem leeren `string[]`. Gehe alle Einträge durch und füge das Fach nur hinzu, wenn es noch nicht enthalten ist (`includes`).
- `durchschnitt(fach)`: Zuerst filtern (`e.fach === fach`), dann die Noten herausziehen (`map`). Ist das Array leer → `return null`. Sonst Summe geteilt durch Anzahl.
- `bestesFach()`: Gehe mit `for (const fach of this.faecher())` alle Fächer durch und merke dir in zwei Variablen das bisher beste Fach und seinen Durchschnitt. `this.durchschnitt(fach) ?? 0` macht aus `null` eine 0.

## Jetzt in VS Code

Baue das Notenbuch auch in deinem Projekt `ts-lernen` – diesmal aufgeteilt auf mehrere Dateien, wie in einem echten Projekt.

> [!WARN] In ts-lernen: Typen mit import type holen
> Node.js streicht beim Ausführen alle Typen weg. Ein Interface existiert danach nicht mehr – und ein gewöhnliches `import { Eintrag }` findet dann nichts. Node.js meldet: *«does not provide an export named 'Eintrag'»*.
>
> Schreibe für Interfaces und Typen deshalb `import type`:
>
> ```ts nocheck
> import type { Eintrag } from "./eintrag.ts";
> ```
>
> Der Zusatz `type` sagt: «Das brauche ich nur für die Typprüfung.» VS Code erinnert dich mit einer roten Linie daran. Klassen, Funktionen und Konstanten importierst du weiterhin ohne `type`. In Angular-Projekten brauchst du `import type` nicht.
